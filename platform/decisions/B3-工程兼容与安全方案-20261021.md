# B3 工程兼容与安全方案（2026-10-21）

状态：**本轮工程实现，待产品/架构确认，不是未经授权的需求基线转正**。

## 1 SSE Bearer 鉴权

原接口-Spec `[待澄清-SSE-AUTH]` 来源于 EventSource 不能添加 Authorization 头。实现改为浏览器 fetch + ReadableStream 解析 SSE，从而直接携带已有 Bearer header。

- URL 不携带令牌，不引入 Cookie 鉴权方案。
- 单项目共享连接、订阅引用计数；工作台/编辑页共同使用同一条流。
- 断流后 2s 查询项目任务列表并后台重连，具名 task/chat.delta/ping 正确处理。
- 服务端每次事件以及 15s heartbeat 复核会话和项目权限；撤权立即终止订阅。
- 前端收到 401 经现有统一鉴权处理，停止连接/轮询/重连。

这是一项兼容已有 Bearer 契约的工程方案，未声称产品批准修改原 Spec。

## 2 生成提交排队与并发限流

现基线存在两个方向：`AC-ED-21` / UI-Spec 要求后提交排队；接口-Spec #43 则写“同项目并发生成>1返回429”。本轮采用：

- 实际 codegen adapter 同项目最多 1 个执行；后提交进入 queued，**不会并发调用**。
- 单项目未终结任务队列最多 20 项；超限返回 RATE_LIMITED（2s 后重试）。
- base_seq 必填，口径为项目当前最大 code_gen task seq；input_hash 为 #42 保存后 tree 原样 JSON.stringify 的 SHA256。
- 任务自身 seq 继续在项目任务序列内单调递增，因此 code_gen seq 可以有间隔。
- 同幂等键返回首次任务，不能绕过序号门禁进行第二次副作用。
- 取消/超时可立即收敛任务状态及退还重试额度；**队列必须等前 worker 实际退出才能放行下一任务**，不能只凭 canceled 状态推断调用已结束。

“最多20项队列”是工程保护参数，**待确认**；文档不把该参数冒充已确认需求。

## 3 元素 ID 项目作用域

ID 原契约为“项目内唯一”。两个项目均可能出现 EL-HOME-001，因此数据库元素/样式/事件键迁移为包含 project_id 的复合主键。

- page 作用域的接口天然知道 project；草稿保存也知道 page。
- 单元素 `/elements/{element_id}` 请求可以带 `project_id` 查询参数。
- 在当前用户可访问范围只命中一个项目时，旧调用不带 project_id 仍可用。
- 多项目歧义返回 INVALID_ARGUMENT，**不猜测目标**；歧义调用方须补 project_id。
- temp_id 仅回执匹配，不作为正式编号分配依据。

新增参数是必要的安全工程兼容方案，**待确认接口详细设计**。

## 4 本地构建代理签名

原 `[待澄清-代理鉴权]` 未裁决。本轮不接受普通网页登录会话冒充可信 L2。

实现要求：已有逐项目鉴权 + 服务端配置 `AD_BUILD_AGENT_SECRET`；客户端代理传：

- `X-Build-Agent-Timestamp`：毫秒时间戳，允许偏差不超过5min。
- `X-Build-Agent-Signature`：HMAC-SHA256 十六进制。
- 签名输入：`task_id:input_hash:timestamp:sha256(JSON.stringify(body))`。
- body：`{passed:boolean,log_digest:string}`，摘要≤2000字符，应由代理脱敏。
- 未配置secret、缺签名/过期/body篡改均403；签名只绑定当前任务和已保存输入。
- 服务端记录来源 `local-build-agent`，界面只有该来源可展示可信构建回传状态。

**本方案是本轮候选工程设计，未得到用户批准；代理分发/密钥轮换/审计/实际本地构建执行尚未验收。** 本轮签名回归使用测试进程临时合成密钥和明确标记的合成报告，未运行任何安卓构建，不能声称 L2 通过。

## 5 草稿修改与正式删除

#42 批量保存会将消失的已持久化节点标记 void。前端删除已有确认弹窗；撤销已持久化的删除会创建新 temp_id，从服务端分配新正式ID，不复活旧ID。

#38 单独删除接口也要求 `confirm=true`，且递归作废子树。本轮额外确认参数未回写为产品基线；待确认。草稿 invalid style / If-Match 冲突拒绝写入，前端本地缓存保留用户输入。
