### 0.2 统一响应包
```json
{ "code": "OK", "message": "", "data": { }, "request_id": "req_..." }
```
- 成功：HTTP 200/201 + `code = "OK"`。
- 失败：HTTP 4xx/5xx + `code` = §0.5 错误码之一 + `message` 为**可直接展示的中文**。
- `request_id` 全链路透传，供问题排查（**不含任何 PRD / 代码内容** —— 敏感数据不入日志与 URL）。

### 0.3 分页 / 排序 / 筛选（**全站统一**，对应 E2）
**入参**：`page`（默认 1，≥1）、`page_size`（默认 **20**，可选 20 / 50 / 100）、`q`（关键词，最长 100 字符）、`sort`（默认 `updated_at:desc`）、`order`。
**出参**：
```json
{ "items": [ ], "page": 1, "page_size": 20, "total": 137, "has_more": true,
  "sort": "updated_at:desc", "failed_parts": [] }
```
- **默认排序**：`updated_at` 倒序；**稳定次序键** = `updated_at` 相同时再按 `id` 升序（避免翻页乱序 / 重复）。
- **上限**：`page_size` 超过 100 → `INVALID_ARGUMENT`；`page` 超出总页数 → 返回空 `items` + `total` 真实值（**不报错**）。
- **`failed_parts`**：**部分来源失败**时列出失败的数据来源（如 `["whiteboard:docx_2"]`），此时 `total` 只统计成功的部分，且**前端必须显示"部分加载"标记，不得当作完整展示**（E5）。
- 各列表的 `q` 匹配字段：项目 → `name`；接口 → `code`/`name`/`path`；待澄清清单 → `title`；Spec → `role`/标题；控件面板 → 控件展示名（**本地筛选，不走接口**）。

### 0.4 长任务：状态查询 + SSE 回传（**对应 E3 / `D-Q15`**）
- 所有长任务（`parse` / `review` / `split` / `spec_gen` / `code_gen` / `verify_l1`）统一模型。
- **查询**：`GET /tasks/{task_id}` → `{task_id, type, status, progress, seq, result_ref, error_code, started_at, finished_at}`
- **推送**：`GET /projects/{project_id}/tasks/stream`（**SSE**）
  - 事件：`event: task` → `data: {"task_id","type","status","progress","seq"}`
  - 事件：`event: chat.delta` → 对话流式输出（**复用同一机制**）；`thread_key` 区分线程〔2026-10-22〕
  - 事件：`event: ai.step` → **平台 AI 处理过程**（任务生命周期 + 大模型调用；同 `step_id` 覆盖式更新，**`at` 保留首次发生时刻**，**新订阅时补发近期步骤**，不落库）〔2026-10-22 新增；2026-10-22 口径：在对话框里**与消息按时间同列混排**，不再是独立区块〕
  - 事件：`event: ping` → 每 15s 心跳（用于发现断线）
  - 头部：`Content-Type: text/event-stream`；`Cache-Control: no-cache`
  - **断线重连**：浏览器 `EventSource` 自动重连；重连后前端以 `GET /tasks/{id}` **按 `seq` 取最新结果**，**只应用序号最新的结果**（`D-A13`，旧响应后到不覆盖新预览）。
  - **超时**：单次任务统一 **5min** 上限；超时置 `timeout`（**可重试**），并推 `task` 事件（`D-A14`）。
- **降级**：SSE 不可用（企业代理拦截等）→ 前端自动降级为**每 2s 轮询** `GET /tasks/{id}`，界面无差别。

**B9生效证明**：`#23` 成功后用返回的 `kb_doc_id` 调 `GET #8`，回读 `doc.version === kb_version`、`doc.content_hash === #23.content_hash`，并逐条确认补充正文存在。**#8 的 content_hash 由服务端对本次返回的 content_md 算 SHA-256**；前端仅比对返回字段，兼容 192.168 局域网 HTTP，不依赖浏览器安全上下文或客户端摘要 API。仅 `changed=true` 且核验成功、自动开关为开才发 `#16 force:true`；缺字段/GET8失败/版本或hash不匹配/正文缺补充 → documentError，停止自动复审并禁用手动复审与写回，不得手动绕过；`changed=false` 不生新版本、不自动重审。 原始上传文件/旧revision只读，与知识库当前版区别；sections_added是处理标题去重，不保证新建；无变化返回原revision/version及zero diff但仍有快照。初次 loadAll 在 GET #17 → GET #8 后比对 `doc.version === prd.version` 与 `doc.content_hash === prd.content_hash`；读取/核验失败清 savedPrd 并置 documentError。`canSubmit` 与 `canWrite` 均要求 `!documentError`；superseded 提示的“重新审核” `disabled=!canSubmit`，独立 `phase=stale` 入口 `disabled=writing || deciding || !!documentError`。核验失败不得从上述手动入口绕过；EL60仍为原五类条件原因，文档错误由已有 EL62 呈现，不新增控件/原因文案。

**#21 关键约束**：`choice` 为空（`unset`）的假设**不允许**进入生成阶段；服务端在 `#23` 前校验，否则 400。
