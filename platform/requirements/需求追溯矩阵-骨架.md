# 需求追溯矩阵（RTM）· 骨架（S4 产出）

> **来源**：`platform/平台需求概要.md` v1.4（第 4 轮回写后 · 门禁已通过）｜ **需求条目表**：`platform/requirements/需求条目表.md`｜ **日期** 2026-10-20
> **本文件是骨架**：REQ-ID / 摘要 / 优先级 / 角色列**已定**，各角色列的具体条目 ID（`UI-*` / `API-*` / `RT-*` / `EVT_*` / `TC-*`）**由对应角色 Spec 产出后回填**，最后由校对 Agent 做覆盖率与孤儿检测。
> **填法与四态**（对齐 `baseline/需求追溯矩阵.md`）：
> - `OK` = 已覆盖，**必须写出 target（具体 ID）**；`GAP` = 有缺口，**必须暴露**；`N/A` = 不适用，**必须写出理由**；`Deferred` = 延后，**必须注明由哪个后续阶段/版本覆盖**。
> - **不允许留空**。"没想好"不是状态，是缺口。
> - 本骨架中：**`—待填` = 该角色负责该 REQ，条目尚未产出**（现阶段计入 `GAP`）；**`N/A` = 该 REQ 未分配该角色**（依据 `需求条目表.md` 的「涉及角色」列，理由统一为「本轮未分配该角色」）。
> - **覆盖状态**列在骨架阶段**一律 `GAP`**（理由：五份角色 Spec 尚未产出），Spec 产出后逐行改为 `OK`/`N/A`/`Deferred` 并填写 target。
