# App 需求包（S4 · 角色 ③）

> **上游**：`platform/requirements/需求条目表.md` + **UI Spec** + **接口 Spec** ｜ **日期** 2026-10-20
> **本包输出到**：`templates/App-Spec.md` → App Spec
> **主输入**：`platform/design/页面规格.md`（11 页面/三态/文案）、`platform/design/数据模型.md`（状态机 §3）、`platform/design/接口契约.md`（SSE、错误码、幂等）
> **主输出**：`RT-*` 路由（与 `UI-*` **一一映射**）+ UI ↔ 接口对应关系 + 页面组织 + 状态管理 + 异常兜底 + **埋点埋码点**（供埋点角色与 S7 开发）
> **依赖顺序**：UI → 接口 → **App（本包）** → 埋点 → 测试。

> **⚠️ 本包主体是「平台自身」的 App（Web 端 B/S 形态的实现口径）**，不是用户被开发的安卓 App。
> 但本包必须**同时**说清两件事：① 平台自身如何组织页面与状态（`RT-*`）；② **平台为用户的安卓工程生成什么**（`REQ-GEN-*`、`REQ-UIEDIT-*`、`REQ-CAP-*`）——后者才是"安卓"这两个字的落点。

## 3 状态管理与异常兜底（通用要求）

| # | 要求 |
|---|---|
| 1 | **状态源唯一**：元素树的当前状态只在 `元素树 + 样式 + 事件` 三处合成（`数据模型 §1.2`），**画布与预览均从它派生，不得反向修改它**；控件树与画布**同一份数据**。 |
| 2 | **列表状态机统一**：`首屏加载 / 翻页加载 / 空 / 无匹配 / 错误 / 部分加载(failed_parts)` 六态互斥可枚举，**空态与无匹配必须分开**，**部分加载不得当作完整展示**。 |
| 3 | **任务态统一消费**：所有 `⚡` 任务共用一套「任务卡片」状态机（`queued/running/succeeded/failed/timeout/canceled` + `progress`），SSE 与轮询**两种数据源产出同一状态**。 |
| 4 | **错误兜底分层**：401 → 跳登录并**恢复草稿**；403 → 统一无权限态（**不泄露存在性**）；404 → 返回上一级 + 刷新列表；409 `VERSION_CONFLICT` → 统一冲突组件；409 `TASK_STALE` → **静默丢弃并提示已用最新结果**；413/422 → 上传页字段级提示；504/503 → 上游不可用可重试态；429 → 倒计时重试；500 → 「出了点问题」+ `request_id`。 |
| 5 | **取消 ≠ 失败**：`canceled` 不得使用错误态样式/文案，不计重试、不新增版本号（`REQ-GEN-005`）。 |
| 6 | **生成失败 ≠ 验证失败**：两个独立组件与文案，各有重试入口（`REQ-GEN-008`）。 |
| 7 | **草稿优先**：任何"未提交就离开"的路径（刷新/关闭/401/超时/网络断）**一律不丢**，恢复时提示。 |
| 8 | **无动效**：拖拽落位、面板展开/收起、选中态切换、预览刷新**均瞬时**（`页面规格§6.4`）；未定义处按无动效处理并在 Spec 中声明。 |
| 9 | **不阻塞**：生成中与解析中**允许继续编辑/提交**，提交串行排队。 |
