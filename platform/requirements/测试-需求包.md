# 测试需求包（S4 · 角色 ⑤）

> **上游**：`platform/requirements/需求条目表.md` + **UI Spec + 接口 Spec + App Spec + 埋点 Spec（四份全要）** ｜ **日期** 2026-10-20
> **本包输出到**：`templates/测试-Spec.md` → 测试 Spec
> **主输入**：`platform/design/验收标准.md`（**118 条 AC + 9 条 E2E**，Given/When/Then，已确认基线 —— **是你的用例源头，不是重复造的东西**）
> **依赖顺序**：UI → 接口 → App → 埋点 → **测试（本包）**。你是最后一道关口。
> **覆盖要求**：**三层（接口 / App / 埋点）分别成节 + 一层 E2E 串联**；每条 REQ **至少 1 条正向 + 1 条异常/边界**；只有正向的视为**未覆盖**；覆盖率必须给出数字。

## 0 用例与 AC 的关系（**先定口径，避免重复劳动**）

| 本 Spec 的产物 | 与 `验收标准.md` 的关系 |
|---|---|
| `TC-<模块>-<三位>` | **可直接由 `AC-*` 转化**：一条 AC 至少转 1 条 TC；**AC 未覆盖的分支由你补**，并把补出的用例回写进 `baseline/需求追溯矩阵.md` 的「测试用例ID」列 |
| `E2E-01`~`E2E-09` | 已在 `验收标准.md §1` 给出（S0→S9）→ 你的 E2E 节**直接引用并细化执行步骤**，**不要另起一套** |
| 三层分层 | **接口层**引用 `接口契约 #n` 与错误码；**App 层**引用 UI Spec 文案与 `RT-*`；**埋点层**引用埋点 Spec 的事件名与触发时机；**E2E** 串起「UI 操作 → 请求 → 返回 → 落库 → 回显 → 埋点」 |

| 层级 | 必须覆盖的最小集合 |
|---|---|
| **接口层** | 逐 `API-*`（被开发 App 的接口）+ 逐 `接口契约 #n`（平台自身接口）：正常入参、缺参、类型错误、越界、无权限、幂等重放、并发、分页边界、空数据返回形态、部分失败（`failed_parts`）、错误码与 message 是否与 Spec 一致 |
| **App 层** | 逐 `RT-*`：元素齐全、文案与 UI Spec 逐字一致、**五种状态**（加载/空/错误/无权限/离线）、跳转与返回栈、接口失败时用户看到什么、权限被拒兜底、弱网与超时 |
| **埋点层** | 逐 `EVT_*`：触发时机精确、参数完整且取值正确、**不重复上报**、**不漏报**（快速连点）、断网补报、漏斗 9 节点可串联、**`canceled`/失败/部分成功不得混入成功** |
| **E2E** | `E2E-01`~`E2E-09` 逐个走通；`E2E-07`（拖拽→生成→验证→预览刷新）是**本期核心**，必须包含"编辑态即时可见且不触发生成"的对照验证 |
