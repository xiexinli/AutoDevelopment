# 埋点需求包（S4 · 角色 ④）

> **上游**：`platform/requirements/需求条目表.md` + **UI Spec（EL-ID 曝光点）** + **App Spec（路由与回调）** ｜ **日期** 2026-10-20
> **本包输出到**：`templates/埋点-Spec.md` → 埋点 Spec
> **依赖顺序**：UI → 接口 → App → **埋点（本包）** → 测试。
> **阶段定位（`§6` / `README §3`）**：埋点**不占独立流程阶段** —— **方案在 S4 定义（本角色）** → **代码在 S7 由 App 角色写入** → **验证在 S8 由测试角色执行**。因此本 Spec 必须写到**能被开发直接埋码、被测试直接判定**的程度。

---

## 0 先分清两条完全不同的"埋点"（**本包最容易做错的地方**）

| | **A. 平台自身埋点** | **B. 被开发项目的埋点方案** |
|---|---|---|
| 埋的是什么 | **AutoDevelopment 平台自己**的用户行为（谁在平台上做了什么） | **用户那个 App** 的业务埋点（用户 App 里的行为） |
| 需求来源 | `§9 补充块⑦`（`D-Q21`）：**做，覆盖主流程漏斗** | `§F5` + `§6` 角色表：**拆解阶段产出埋点方案** |
| 编号 | `REQ-TRACK-001`~`003` | `REQ-SPLIT-004` |
| 载体 | 平台侧事件上报（`接口契约 #62 POST /metrics/events`，批量 + 失败静默重试） | `TrackPlan` 实体（`数据模型 E12`）：`event_key` + `trigger_desc` + `params` + `element_id` + 状态四态 |
| 事件命名 | **你（埋点角色）定义**（本包要给方案，不是给一个名字） | `EVT_<模块>_<动作>`，**项目内唯一** |
| 谁写代码 | 平台开发 | **App 角色按你的 Spec 写入用户安卓工程**（S7） |
| 谁验证 | 测试角色（`AC-TR-01/02`） | 测试角色（`E2E-08`：埋点方案在 S8 被验证） |

> 两者**互不替代**，**都要在本 Spec 中成节**。

## 1 ★ 三条硬约束（写 Spec 前先固化）

| # | 约束 | 依据 |
|---|---|---|
| 1 | **埋点不通过事件面板上报**。埋点由 **S4 定方案 → S7 写进代码**；事件面板只生成**空回调存根**（`action_type` 本期仅 `none`）。这是**两条独立路径**，**不得**在 Spec 里把它们合流 | `§F14 补充块⑩`（`D-Q13`）；**约束 4** |
| 2 | 埋点必须绑定 **`EL-<模块>-<三位>` 元素 id**（曝光点/点击点所在元素）。该 id 是「网页拖拽控件 ↔ 原生安卓控件 ↔ 埋点曝光点 ↔ 测试用例定位」的**统一主键** | `README §4.1`；`REQ-UIEDIT-009` |
| 3 | 埋点上报**不得包含 PRD 正文与生成的业务代码内容**；个人信息类字段须标脱敏要求 | `§9 补充块③`（`D-Q7`）；`REQ-AUTH-005` |

## 2 埋点需求包（表）

| REQ-ID | 需求摘要 | 埋点关注点 |
|---|---|---|
| `REQ-PROJ-001` | 新建项目 | 漏斗**节点 1**：项目创建成功。触发时机须**可判定**（"创建接口返回 201 且列表已插入该项目后"，**不是**"点击新建按钮时"）；参数至少含 `project_id`（**脱敏口径由你定**，不得含项目名以外的用户内容除非必要）；**区分"点击新建"与"创建成功"**两个事件（点击但被校验拦截 = 另一事件） |
| `REQ-PROJ-002` | 项目列表 | 列表曝光/搜索/翻页属**辅助事件**（可选）；**若提，必须回答"要用数据回答什么业务问题"**（`埋点角色` 硬要求）；不设事件也要在 Spec 中显式写「不提，理由：无业务问题」 |
| `REQ-UPLOAD-001` | 上传与解析 | 漏斗**节点 2**：解析任务到达终态（`succeeded` / `partial` / `failed` **三个取值都要有**，`partial` 不得混进成功）；参数含分块失败数与耗时；**触发时机 = 任务状态回调**，不是"点击开始解析" |
| `REQ-REVIEW-001` | 门禁审核 | 漏斗**节点 3**：门禁结果产生（`passed` / `blocked`）；参数含阻断项数、`revision_id`、`standard_version`；**"提交审核"与"审核完成"是两个事件** |
| `REQ-CHAT-001` | 对话 | 对话消息发送/回复完成；**空消息被拦截要单独区分**（`埋点角色` 硬要求：区分"点击成功触发"与"点击但被拦截"）；**事件参数不得携带消息正文**（含 PRD 内容风险，`REQ-AUTH-005`） |
| `REQ-SPLIT-001` | 需求拆解 | 漏斗**节点 4**：拆解完成；参数含 REQ 总数、5 个角色包各自的条目数（用于判断哪类角色总在缺需求）；含模型耗时 |
| `REQ-SPLIT-004` | 埋点方案（被拆解项目） | ★ **本包 B 线主战场**：为**用户的 App** 产出 `TrackPlan`：每个事件给 `event_key`（`EVT_<模块>_<动作>`）、**精确触发时机**（例："点击提交按钮且校验通过后、发请求前"）、参数（名/类型/取值）、**埋码点**（页面 `RT-*` / 元素 `EL-*` / 哪个回调如 `onClick`）、去重规则、上报时机（即时/批量/退出）、对应 `REQ-ID`；状态随 S4→S7→S8 走 `draft→confirmed→implemented→verified` |
| `REQ-SPEC-001` | Spec 生成 | 漏斗**节点 5**：Spec 生成完成（**部分成功要可辨识**：`succeeded[]` / `failed[]` / `overall`）；参数含各角色耗时（对应"Spec 生成 ≤5min/份"指标） |
| `REQ-UIEDIT-001` | 拖拽与生成（编辑） | 漏斗**节点 6**：提交编辑变更（生成任务创建）；参数含元素数、控件类型分布、`page_id`；**拖拽落点被拒收**是独立事件（区分"拖了但没放成"） |
| `REQ-UIEDIT-004` | 事件面板 | **只埋"配了哪类事件（点击/长按/双击）"**，**不埋**动作语义（本期 `action_type` 只有 `none`，无跳转/接口/上报可言）；**重申**：埋点本身**不经事件面板** |
| `REQ-UIEDIT-009` | 元素 id | 所有曝光/点击事件的定位键必须**严格使用归一化后的 `EL-<模块>-<三位>`**（大写零填充），**禁止**用别名或临时 id 上报；作废（`void`）的 id **不得再产生新事件** |
| `REQ-GEN-001` | 生成任务 | 漏斗**节点 7**：生成任务创建（入队）与终态；用于计算**入队→成功**的转化与排队时长 |
| `REQ-GEN-005` | 停止生成 | **取消是独立事件**（`canceled`），**不得与失败合并**；参数含取消时的 `progress`（用于判断"用户在哪一步失去耐心"）；口径与 `REQ-NF-001` 的重试计数**互不影响** |
| `REQ-PREVIEW-001` | 预览 | 漏斗**节点 8**：预览刷新完成（L1 通过后）；参数含 `seq`、耗时（L1）。**L2 本地构建结果回传**是独立事件（**仅记录、不计平台指标**，`REQ-NF-001`） |
| `REQ-AUTH-004` | ★ 外发大模型告知与开关 | **合规相关事件**：告知弹窗展示 / 用户确认 / 用户关闭开关；关闭后的"生成不可用"须有事件（用于证明**没有静默降级**）。**不得**上报 PRD 正文 |
| `REQ-DELIVER-001` | 交付归档 | 漏斗**节点 9**：交付完成（导出/下载成功）、导出被拒（403）；用于漏斗收口率 |
| `REQ-TRACK-001` | 平台自身埋点（漏斗） | ★ **本包 A 线主战场**：给出**完整事件字典**（事件名、触发场景、精确时机、参数名/类型/取值、上报时机、去重规则、对应 `REQ-ID`）+ **漏斗定义**（9 节点顺序与各节点绑定的事件）+ **公共参数**（用户标识用 `open_id` 的**脱敏/哈希口径**、设备、版本、会话、来源页、上一页）+ **数据校验方法**（每个事件如何验证上报正确，含断网补报） |
| `REQ-TRACK-002` | 生成成功/失败与耗时 | 事件须**同时覆盖成功与失败**并带耗时；**耗时口径与 `REQ-NF-001` 严格一致**：**L1 计入指标、L2 仅记录**（**不得**把 L2 耗时混入 L1 指标，否则指标失真） |
| `REQ-TRACK-003` | 上报降级与合规 | 上报走 `接口契约 #62` **批量**接口，**失败静默重试、不阻塞业务**；**上报体绝不含 PRD 正文与生成代码**；上报失败不得影响任何业务流程，也不得在界面上暴露上报错误 |

## 3 漏斗定义（`AC-TR-01` 的判定依据，必须能**逐节点还原**）

```
节点1 新建项目 → 节点2 上传解析完成 → 节点3 门禁通过 → 节点4 拆解完成
  → 节点5 Spec 生成完成 → 节点6 提交编辑变更 → 节点7 代码生成完成
  → 节点8 预览刷新 → 节点9 交付完成
（旁路：[代码生成失败] / [生成取消] / [验证失败] / [外发开关关闭] 四个负向事件）
```

| 节点 | 事件归属 REQ | 判定口径（**必须精确到可判定**） |
|---|---|---|
| 1 | `REQ-PROJ-001` | 创建接口返回成功且项目出现在列表中之后 |
| 2 | `REQ-UPLOAD-001` | 解析任务进入终态（`succeeded`/`partial`/`failed` 分别上报） |
| 3 | `REQ-REVIEW-001` | 评分卡 `verdict` 产生（`passed`/`blocked`） |
| 4 | `REQ-SPLIT-001` | 拆解任务成功，5 个角色包落库后 |
| 5 | `REQ-SPEC-001` | `specs:generate` 返回（含 `overall`）之后 |
| 6 | `REQ-UIEDIT-001` | 生成任务（`GenTask`）创建成功、返回 `task_id`+`seq` 之后 |
| 7 | `REQ-GEN-001` | 生成任务终态（`succeeded`/`failed`/`timeout`；`canceled` 走旁路） |
| 8 | `REQ-PREVIEW-001` | **L1 `passed` 且预览内容已替换**之后 |
| 9 | `REQ-DELIVER-001` | 交付归档完成 / 导出成功之后 |

**负向事件（本期必须埋，用于定位流失）**：代码生成失败（`REQ-GEN-008`）、验证失败（`REQ-GEN-004`）、生成取消（`REQ-GEN-005`）、外发开关关闭导致生成不可用（`REQ-AUTH-004`）。

## 4 埋码点要求（写给 S7 的 App 角色，**每条必填**）

| 列 | 要求 |
|---|---|
| 页面 | `RT-*`（App Spec 的路由 ID） |
| 元素 | `EL-<模块>-<三位>`（**唯一主键**，不得用别名） |
| 回调 | 具体回调名（如 `onClick` / `onResume` / 任务状态回调 / SSE 事件处理），**不允许**写"页面加载时""操作时"这类不可判定的表述 |
| 时机 | 精确到"某动作成功/失败之后、某请求之前/之后" |
| 去重 | 同一次用户意图只上报一次（幂等/取消重试/旧响应后到均不得重复计数） |

**易错点（本 Spec 必须逐个表态）**：
- **旧响应后到**（`REQ-GEN-006`）：被丢弃的旧结果**不得**上报"生成完成"。
- **幂等重放**（`REQ-NF-006`）：3s 内重放**不得**二次计数（`REQ-PROJ-001` 连点新建）。
- **取消**（`REQ-GEN-005`）：`canceled` 只报取消事件，**不得**同时报失败或成功。
- **部分成功**（`REQ-UPLOAD-003` / `REQ-SPEC-001` / `REQ-CAP-002`）：**不得**上报为成功。
- **SSE 重连**（`REQ-GEN-007`）：重连后按 `seq` 取最新，**不得**因重连重复上报同一任务终态。
