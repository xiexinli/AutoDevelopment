# A9 对话框：回复「完成」却不实时落位（2026-10-23）

## 现象（用户报障）

审核页悬浮对话框里发送消息后：

- agent 处理过程条目走完 —— `调用大模型生成回复 · 完成 / 输出 N 字`；
- 但**回复气泡不出现**，要**再发一条消息**才「冒出来」。

## 根因（两个缺陷叠加）

`chat.delta` 的**冻结字段**是 `{message_id, seq, delta, thread_key}`（`接口-Spec §5.0.3`）——
**不带 `created_at`**。前端 `web/src/sse/stream.ts` 的 `watchChat` 因此把流式消息的
`created_at` 兜底成 `""`：

1. **排到时间线最前**：`ChatPanel` 的 `feed` 按 `atMs(m.created_at)` 排序，`""` → `at = 0`
   → 该条被排到「消息 + 步骤」同一条时间线的**最前面**（用户消息在底部），而面板只自动滚到底，
   于是这条回复**看不见**。
2. **校正结果被丢弃**：`ChatPanel` 的 `setItems` 合并只比 `message_id` / `content`，
   `created_at` 不在比对范围。`#25` 轮询（15s 一次）拿到权威行后内容相同 → **返回 `prev`**，
   错误位置一直保持。只有 `#26` 成功后那次 `listChatMessages`（`setItems(r.items)` 直赋）
   才会把它摆正 —— 这正是「再发一条消息就显示出来」的成因。

## 修复（**纯前端**，契约零变更）

`web/src/sse/stream.ts`（`watchChat`）：

- 流式消息的 `created_at` 以**到达时刻**兜底：`m.created_at ?? previous?.created_at ?? new Date().toISOString()`；
- 收到 `done: true`（服务端此时**已落库**）→ `void tick()` 拉一次 `#25`，用权威 `created_at` / `status` 校正本地推测值。

`web/src/pages/ChatPanel.tsx`（`setItems` 合并）：

- 逐字段比对**增加 `created_at` / `status` / `thread_key`**，让 `#25` 的校正结果能真正生效
  （此前只比 `content`，校正被静默丢弃）。

**未新增接口 / 未改字段 / 未改编号**（接口 75、事件 54、元素 425、测试 600 均不变），
故**不涉及** Spec 冻结表与一致性计数。
