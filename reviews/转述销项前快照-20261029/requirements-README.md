## 角色依赖顺序（**串行，上游未定稿下游不得开工**）

```
需求条目表 → ① UI Spec → ② 接口 Spec → ③ App Spec → ④ 埋点 Spec → ⑤ 测试 Spec
                        （接口从 UI 的《元素-数据需求表》倒推；App 把 UI 与接口绑成对应关系；埋点挂 EL-ID）
```

| 角色 | 输入 | 输出 | 关键硬约束 |
|---|---|---|---|
| ① UI | 需求条目表 + UI 需求包 + `页面规格.md` + `数据模型 §4` | `UI-*` / `EL-*` / 文案逐字 / **《元素-数据需求表》** / **近似渲染差异清单** | `EL-ID` 一元素一 id、全局唯一、不可复用；色彩/字号给具体数值 |
| ② 接口 | **UI Spec 的《元素-数据需求表》** + 接口需求包 + `接口契约.md` | `API-*` + **《UI 数据供给对照表》零缺口** | **从 UI 倒推**；枚举穷举禁「等」；字段名与 App Spec 逐字一致 |
| ③ App | UI Spec + 接口 Spec + App 需求包 | `RT-*`（与 `UI-*` 一一映射）+ 状态管理 + 异常兜底 + **埋码点** | 只出源码、本机构建；**由 Spec 直出代码并写回所选工程根**；**事件只给空回调存根** |
| ④ 埋点 | UI Spec（`EL-ID`）+ App Spec（`RT-*`/回调） | `EVT_*` 事件字典 + 埋码点 + 漏斗 **8 节点** | 每个事件挂 `REQ-ID`+`UI-ID`+`EL-ID`；触发时机可判定；**不经事件面板**；**「编辑」节点已从主流程漏斗移除**（`K3`） |
| ⑤ 测试 | 上述四份 + 测试需求包 + `验收标准.md` | `TC-*` 三层 + E2E + 覆盖率 | 每条 REQ **≥1 正向 + 1 异常**；预期结果可判定 |

## 本次拆解遵守的 8 条项目约束（防拆错）

1. 平台**只交付源码**，安卓编译在**用户本机**完成，不做服务端构建；
2. 耗时：**L1 P95 ≤ 90s**；**L2 仅记录、不计平台指标**；
3. 预览是**生成构件的静态预览**（本期形态仍为网页近似渲染），UI 需求包已列**差异清单**，真机以本地构建为准；
4. 事件面板**只生成空回调存根**（`action_type` 仅 `none`），不设计"面板内配跳转/调接口"；
5. **外发第三方大模型的告知与开关是 P0 合规项**（`REQ-AUTH-004`，UI / 接口 / App 三份都覆盖）；
6. 属性面板 **11 项**、事件面板 **3 项**，**以 §F14 为准**；
7. `REQ-UIEDIT-005`（控件树）、`REQ-KB-002`（知识库入口）**有正式需求来源**；
8. `[来源: 推断，待确认]` 条目**不阻塞开工**，引用时**原样带标签**。
