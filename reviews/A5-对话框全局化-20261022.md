## 一、做了什么

### 1.1 对话框 = 全局悬浮窗（每个已登录页面）

| 项 | 实现 |
|---|---|
| 载体 | 新增 `web/src/components/FloatingChat.tsx`，由 `AppShell`（全局外壳）挂载 → **每个已登录页面都有** |
| 形态 | 右下角 **52px 圆形按钮** → 展开为 **400×560 可拖动面板**；`Esc` / 收起按钮收起 |
| 约束 | 沿用「**无动效**」口径：仅拖动跟随指针，无位移/循环动画；按钮可聚焦（`aria-label`） |
| 原位置 | 工作台右栏的 `ChatPanel` 已**移除**（同一份组件改为嵌入悬浮窗，不再重复渲染两个对话） |

### 1.2 主体对象随页面切换（会话按主体分线程）

- **服务端**：`tbl_chat_message` 增 `subject_type` / `subject_id` 两列（老库**增量迁移** + 建索引；
  历史消息统一归入 `project` 线程，**升级后旧对话不丢**）。
  `#25` 支持 `?subject_type=&subject_id=`（**不给则返回全部** —— 保持既有行为）；
  `#26` 请求体可选 `subject_type`/`subject_id`；**序号在「项目 + 主体」范围内单增**；
  `chat.delta` 事件带上主体，前端据此过滤，避免串台。
- **前端两层主体**（`web/src/chat/subject.ts`）：
  - **路由默认**（`AppShell` 按路径写入）：`kb`→`kb_doc`、`specs`→`spec`、`apis`→`api_def`、`versions`→`version`、其余→`project`；
  - **页面覆盖**（各页写入**当前选中的具体对象**）：知识库打开某篇文档 → 文档标题；Spec 页选中某份 Spec；
    接口页正在编辑的接口；版本页所选版本。**覆盖仅当类型与当前路由一致时生效**（避免上一个页面残留串台）。
  - 为什么分两层：`AppShell`（父）的 effect **晚于**页面（子）执行；若共用一个变量，父层会把子页面的覆盖冲掉。

### 1.3 AI 处理过程（在对话框中展示）+ **两个真实缺口一并修掉**

- 后端 `core/ai-trace.ts`：`aiStep()` 推 `ai.step`；`traceLlm()` 包住一次大模型调用（耗时 + **规模性**描述，如「输出 56 字」，**不含正文**）。
  任务生命周期由 `core/tasks.ts` 的 `emit()` 一并推送（解析 PRD / 门禁审核 / 需求拆解 / 生成 Spec / 生成安卓代码 / L1 验证）。
- **缺口 ①（补发）**：过程原本只在组件内存里 —— **悬浮框一收起再打开就空了**，且审核/拆解/Spec 是在别的页面触发。
  修法：服务端加**内存环形缓存**（≤60 条 / 30 分钟，**不落库**），`#45` **新订阅时补发**；
  前端再加**模块级缓存**（`stream.ts`），因为 SSE 是**按项目共享的长连接**，面板重挂载**不会重建连接**，服务端补发这一次拿不到 —— 两层互补。
- **缺口 ②（真 bug）**：任务类步骤原先直接 `publish()`，**没进缓存** → 补发时只剩大模型那类步骤。已统一走 `aiStep()`（唯一入口）。
