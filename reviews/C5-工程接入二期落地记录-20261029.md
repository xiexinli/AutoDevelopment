## 1 做了什么

### 1.1 补丁引擎 `server/src/adapters/patch.ts`（新增）

把生成物当作**补丁集**写回用户在 `#73` 登记的既有工程根。**六条安全边界逐条落地**：

| # | 边界 | 实现 |
|---|---|---|
| 1 | **只写登记工程根内** | 相对路径校验（拒 `..`/绝对/盘符/非法字符）+ `resolveInside()` 归一化后再比对（双保险） |
| 2 | **硬禁碰** | `gradle/wrapper/**`、`gradlew(.bat)`、`local.properties`、`*.jks`/`*.keystore`/`*.pepk`、`.git/**`、`.gradle/**`、`.idea/**` → 一律拒绝 |
| 3 | **冲突不静默覆盖** | 目标已存在且内容不同 → **整批拒绝**（`VERSION_CONFLICT`），需显式 `overwrite:true`；**未写入任何文件** |
| 4 | **写前快照** | 被替换文件先复制到 `<AD_PATCH_DIR>/<patch_id>/<相对路径>`；创建的文件登记在案 |
| 5 | **原子落盘** | 先写 `<target>.ad-tmp-<patch_id>` 再 `rename`（`D-A16`）；**中途失败自动回滚已写文件**，不留半成品 |
| 6 | **既有 id 不可静默删除（L1）** | 替换 `res/layout/*.xml` 时比对 `@+id/*` 集合；**丢失既有 id → 拒绝**并列出被删 id，需显式 `allow_id_removal:true` |

**回滚**：`replace` → 从快照还原；`create` → 删除（并清理空目录）。

### 1.2 路由 `server/src/routes/patches.ts`（新增；已注册 `app.ts`）

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| N4 | `POST` | `/projects/{project_id}/patch-applications` | **应用补丁**（自动写）：`{files[], confirm:true, message?, overwrite_all?}`；须项目已接入（`source_kind=imported` + `engineering_root`）；**提交类幂等**（同键重放返回首次结果 + 首次 201）；出参含 `totals` / `entries`（含 `removed_ids`）/ `rollback` 指引 |
| N5 | `GET` | `/projects/{project_id}/patch-applications` | 补丁列表（倒序，最多 50；含 `status`（`applied`/`rolled_back`）与文件清单） |
| N6 | `POST` | `/projects/{project_id}/patch-applications/{patch_id}/rollback` | **回滚**（`⬛` 二次确认）：`replace` 还原、`create` 删除；重复回滚 → 400 |

manifest 落 `tbl_project_meta['patch_sets']`（**不新增实体**，遵守「只做 23 个实体」）。
