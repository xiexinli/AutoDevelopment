# A8 · 对话框：agent 处理过程与用户消息**共用一个列表**

日期：2026-10-22 ｜ 范围：`web/src/pages/ChatPanel.tsx`、`server/src/core/ai-trace.ts` 与五份 Spec 的同步
口径来源：PM 2026-10-22 18:36 —— 「对话框：agent 内容和用户发的消息共用一个列表」

## 一、改动前的问题

对话框是**两块**：

| 区域 | 内容 | 滚动 |
|---|---|---|
| 上部「AI 处理过程」（`EL-WORK-035`） | 可折叠区块，标题行 `AI 处理过程` + 汇总（`{n} 步已完成` / `{n} 项进行中 · 共 {m} 步` / `{m} 步完成 · {n} 项失败`） | **独立**滚动区（最高 190px） |
| 下部消息区 | 用户 / 平台消息气泡 | 独立滚动 |

两条滚动条、两块视觉分区，agent 做的事与对话割裂。

## 二、改动后

**一个列表、一条时间线**：agent 的步骤作为**列表条目**与用户/平台消息**按时间混排**，随消息列表一起滚动；独立折叠区块、标题行与汇总文案**整体删除**。

| 项 | 做法 |
|---|---|
| 排序键 | 步骤 `at` × 消息 `created_at`，升序；**同一时刻消息在前** |
| 步骤条目样式 | 最大宽 320px（与气泡同列宽）、底 `C-10`、四边 `C-13` 1px、`R-8`、内边距 `SP-8`/`SP-10`；图标：运行中 `C-01` 转圈 / 完成 `C-06`✓ / 失败 `C-04`✕ / 取消 `C-16` |
| 原地更新 | 同 `step_id` 覆盖式更新（不追加新行），最多 60 条 —— 语义不变 |
| 自动滚动 | 新消息 / 新步骤 / 等待回复 → 列表滚到底（取代原「进行中步骤自动展开」） |
| 空态 | `feed.length === 0` 才显示「这个步骤还没有对话…」；**有步骤、无消息时不算空** |
| 无步骤 | 列表**只有消息、不出现空态**（不再有「整块不渲染」的区块） |

## 三、同时修掉的一个真缺陷（混排才暴露）

**`ai.step.at` 原本会被刷新**：`aiStep()` 每次调用都 `at: nowIso()`，而 `traceLlm()` 在**完成**时又推一次 —— 于是步骤的 `at` 是「完成时刻」。

混排后实测复现：**已完成的步骤落到它产生的那条回复之后**（截图 `/tmp` 阶段可见），读起来是倒的。

修法（`server/src/core/ai-trace.ts`）：**同 `step_id` 的后续更新沿用首次发生的 `at`**，只刷新 `status`/`title`/`detail`/`duration_ms`/`progress`。

```ts
const prev = step.at ? undefined : (recent.get(projectId) ?? []).find((s) => s.step_id === step.step_id);
const full: AiStep = { ...step, at: step.at ?? prev?.at ?? nowIso() };
```

## 七、已知取舍（**未擅自改，待 PM 定**）

**步骤是项目级、消息是线程级**：`ai.step` 不带线程信息（与改动前一致 —— 原区块同样按项目、跨线程可见）。因此**切到别的子步骤（如知识库）时，仍会看到工作台线程产生的步骤条目**（实测见 §四）。

要按线程隔离，需给 `ai.step` 加 `thread` 字段（服务端在推步骤时带上当前阶段 / `thread_key`）—— 这是**契约变更**（要动 `接口-Spec` / `App-Spec` / 测试用例），**本轮未做**。

## 八、未覆盖（不声称已核）

1. 步骤条目在**超长列表（60 条）+ 大量消息**下的滚动性能未实测。
2. **切线程瞬间**的滚动位置保持未逐项核对（只核了渲染不崩、列表内容正确）。
3. 混排的**同一毫秒**边界（步骤与消息时间戳完全相等）只按「消息在前」的稳定规则处理，未构造实测。
