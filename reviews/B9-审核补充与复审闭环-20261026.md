## 2 服务端磁盘现状

### 2.1 #17：报告版本与当前 PRD 分离

**#8本次补正**：`server/src/routes/kb.ts`返回`{...d,content_hash:digest(d.content_md)}`；digest为Node `createHash("sha256").update(s).digest("hex")`，哈希对应本次返回的content_md，不是旧摘要/新增DB列。`fetchKbDoc`明确返回`document_id:string|null`和`content_hash:string`；局域网192.168 HTTP前端不计算摘要，直接对比GET8与#17/#23字段。


GET `/api/v1/reviews/{review_id}` 新增：

```text
prd = { revision_id, document_id, kb_doc_id, version, content_hash } | null
```

- 顶层 `revision_id` 保持**报告绑定输入**；`prd.revision_id` 来自项目 `current_revision_id`，`prd.kb_doc_id/version` 来自该文档的 PRD 知识库行。
- `content_hash = SHA-256(kb.content_md)`；无当前 revision 或对应 PRD KB 行时 `prd=null`。读取历史报告不等于重新审核。
- GET #18 实际字段集：`{item_code,group,group_title,level,verdict,evidence_ref,suggestion,accepted,supplement}`；`evidence_ref` 实际是 string，`verdict` 为 pass/fail/na；`group_title` 用于分组，不是落章标题。

### 2.2 #20、#21、GET #19：规范化与 convert 归档

- #20 对 `String(answer ?? "")` 去掉**起始** `__other` 再 trim；空串/空白/仅标记拒绝为 INVALID_ARGUMENT「请先填写答复。」；允许非空自由文本，不把不属于 options 的文本一律视为非法。
- #20 单独保存 `answer/status=answered`，**不产生 PRD 新版本**，不能拿 answered 代替已写正文证明。
- #21 POST 响应 `converted_question_code`：convert 为 `{assumption_code}_converted`，accept 为 null。convert 创建或恢复 blocking 问题；accept 将对应问题置 `status=converted`（归档但保留 answer）；再 convert 按 trim(answer) 恢复 answered/open，不重复建题。
- GET #19 排除 `status=converted`。该标识是响应派生信息，不声称 `tbl_assumption` 新增了持久列。

### 2.3 #23：原子保存、保正文、可核验版本

请求沿用原 API，增加 optional `answers:[{question_code,answer}]`，与 optional `supplements:[{item_code,text}]` 同次写入：

1. `confirm=true` 与 `snapshot=true` 必须；校验假设全已选、报告当前、KB 可用、`revisionText(rev) === kb.content_md`。
2. `answers` 必须数组、两个字段为 string、question_code 必须属于本报告未归档题；同 code 后值覆盖，规范化后与已保存答案合并；任何 blocking 题合并后空答→整次拒绝。未知/跨报告/归档问题拒绝，不保存一半。
3. `accepted_items` 未提供时当前实现按 `[]`；未知编号拒绝。补充 trim、按 item_code 后值去重；只有已采纳的非空补充生效，生效项必须属于报告且 verdict=fail。未 Accept/空白忽略，不把无效编号均写成“无错忽略”。
4. 补充小节标题取**该报告 standard_version**：title 缺失或恰为历史 GROUP_TITLES 的组名，仅在落章时映射 DEFAULT_ITEM_TITLES；自定义标题保留、清理标题换行，**不改历史标准版本**。
5. `upsertSection` 跳过代码围栏里的标题，匹配同名1~6级标题，在下一个同级/更高标题前插入；该节已有完整片段则不重复写，否则无标题才文末新增。原有标题、子节、围栏和正文保留；因为可以节中插入，**不能要求整个旧文永远是新文的字节前缀**。
6. 未归档非空答复与非 unset 假设选择汇入「澄清答复」；只采纳而无有效补充的 suggestion 汇入「评审采纳建议」。有标题、勾采纳、写回成功均**不意味着 pass**，不得把“补齐××”一句说明当完成需求。
7. 一次事务保存答案/status、采纳集合、原文快照、有效 supplement；正文 changed 才 KB version+1 并经 materializeEditedRevision 生成同 document_id 新 revision、不可变正文快照、更新 current_revision_id/作废旧审核；事务错误整体回滚。

响应同集（接口冻结表、详细契约、App/测试/设计本轮均同步）：

```text
deleted_lines, modified_lines, added_lines,
diff_summary { deleted_lines, modified_lines, added_lines },
changed, new_revision_id, kb_doc_id, kb_version, content_hash,
sections_added[], snapshot, snapshot_id
```

- flat 三项与 diff_summary 同值，保老调用兼容；删除/修改固定0，added_lines 为 changed 时新旧 `split("\n").length` 差（不是语义逐行 diff）。
- `changed=false`：不生新 revision、不增 KB version、不作废报告，回原 revision/现 version 与 zero diff；仍保存快照。不能因200重复自动审。
- `sections_added` 是本次处理的 landed 标题去重，即使并入旧节/无变化也可能包含标题；**不是一定新建的小节数量**；仅 leftover 建议清单不单独列进 landed。

### 2.4 #16 force 与继承：真实 verdict 不得被采纳态覆盖

- 保留非 force 复用分支，顺序在兜底前：同 revision/standard_version/depth 的已有报告照常复用，不因旧问题使刷新被拦。
- 仅 force=true 且**同 revision**存在未 superseded 既有报告，检查阻断题未 answered/converted 和 choice=unset，拒绝不建任务。
- 找上一报告按同项目、同 document_id 的 passed/blocked 报告，按 item_code 取历史值。旧 supplement 只有当前审核正文包含其全文才继承，另一份上传文档即使同名/同字节也不能串台。
- `accepted`只在新verdict=fail、旧accepted且（有效正文supplement 或 `prev.suggestion===it.suggestion && !!prev.suggestion && markdown.includes(prev.suggestion)`）时继承。same-suggestion支已要求非空且建议全文在当前审核markdown；不再列“未落实内容被继承”缺口，仍不覆盖模型verdict/counts。
- 模型本轮 `verdict/counts` 不被 accepted/supplement 自动改写，fail 要保留并继续修正；新模型仍判 fail 不是“失败项无需再审”。

## 3 前端磁盘现状

### 3.1 提交 disabled，而非仅点击拦截

```text
busy = writing || deciding || loading
blockingOpen = blocking题中 normalizeAnswer(当前答案) 为空的数量
dirty = 任一规范化当前答案/trim补充 与已加载的落库值不同
revisionChanged = 当前PRD revision !== 报告revision
canSubmit = 有reviewId && !documentError && !busy && !blockingOpen && !unset && !dirty && revisionChanged
canWrite = !writing && !deciding && !loading && !superseded && !unset && !blockingOpen && !documentError
```

- **fail评分项/failed items数量本身不是 disabled 条件**，否则用户修正后永远不能发真实复审。
- EL26与EL50确认按钮同条件、确认时再次检查；正常 disabled 不弹窗、不发 #16，也不能声称点击禁用按钮仍会高亮定位或发阻断点击事件。
- 同 revision 没有新的已写入内容不重复提交；输入仅在内存中/采纳未确认时仍 dirty，不把勾选等于已写入。
- 两个写回入口 canWrite：不在保存/选择/审核中，未 superseded，无 unset，无阻断空答且 !documentError；EL52再检查“零勾选**且**无非空答复”才禁用，允许0项只写答复。

### 3.3 先回读核验，再自动复审

`#23成功 → GET #8(kb_doc_id) → version/hash/补充存在性核验 → changed且自动开才 #16 force:true`

- 需要kb_doc_id/new_revision_id/content_hash；比较`GET8.version===#23.kb_version`和`GET8.content_hash===#23.content_hash`，每条提交补充须在正文。摘要由#8服务端对本次content_md算SHA-256；前端不依赖浏览器安全上下文/客户端摘要API。
- 缺字段、GET8失败、version/hash不一致、正文缺补充均显示错误、**不自动审核**；`changed=false`显示无变化，不自动审核。
- 自动审核仍是设备级偏好 `ad.v1.device.reviewAuto`、默认开；无报告可自动开审；两个自动分支不报 EVT_review_submit。
