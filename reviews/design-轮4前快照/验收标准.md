## 1 P0 主流程端到端（S0→S9）★ 对应 G2

> 这条路径必须**一条不漏**地通过，才算本期交付成立。

### E2E-01 S0 新建项目 + 建知识库
- **Given** 用户已登录（⚠️ `[待PM确认-D-Q6]`）
- **When** 新建项目，名称为 `点餐 App`
- **Then** ① 列表首位出现该项目，`stage = created`；② 知识库为空但**视为就绪**（`kb_ready` 可达）；③ **不出现任何报错**

### E2E-02 S1 上传与解析
- **Given** E2E-01 完成
- **When** 上传一份 20 页内的 `.docx`（含 1 张内嵌表格）
- **Then** ① 30s 内完成；② `parse_status = succeeded`（或 `partial` 且**明确标黄列出**未取到的块）；③ 生成 `document_id` + `revision_id`；④ 再次上传同一文件 → **产生新 revision，旧 revision 仍可查**

### E2E-03 S2 门禁审核
- **Given** E2E-02 完成
- **When** 触发门禁审核
- **Then** ① 产出评分卡（A~I 逐项 + **每项带证据行号**）；② 产出待澄清清单，按 阻断/重要/建议 分组；③ 评分卡绑定该 `revision_id`；④ **PRD 更新后旧评分卡显示「已过期」**

### E2E-04 S3 对话补充 → 复审
- **Given** 存在 ≥1 项阻断
- **When** 在聊天框补充并提交复审
- **Then** ① 产生**新**评分卡，旧卡置 `superseded`；② 阻断项数**减少或不变但不增加**；③ 阻断项 = 0 时 `stage = gate_passed`

### E2E-05 S4 需求拆解 + 埋点方案
- **Given** `gate_passed`
- **When** 触发拆解
- **Then** ① 产出 5 个角色需求包，REQ-ID **项目内唯一**；② **埋点方案在本阶段产出**（`TrackPlan` 状态 `confirmed`）；③ 同时只有一个拆解任务（重复触发 → 提示「上一次拆解还没结束。」）

### E2E-06 S5 Spec 生成（五份，Markdown）
- **Given** E2E-05 完成
- **When** 生成 Spec
- **Then** ① 生成顺序 **UI → 接口 → App → 埋点 → 测试**（串行）；② 5 份均为 `.md` 且**相互独立**；③ **单份失败不阻断其余**，`overall` **绝不显示为成功**

### E2E-07 S7 编辑 → 生成 → 验证 → 预览刷新 ★ 本期核心
- **Given** Spec 就绪，进入可视化编辑页
- **When** 拖入 1 个 `BUTTON` → 改背景色 → 配「点击」→ 点「提交变更」
- **Then** ① 编辑态样式改动 **即时可见**且**不触发**生成；② 生成任务入队，状态条显示「正在生成代码…」；③ **L1 通过 → 预览自动刷新**，显示「生成 #{seq} · {时间}」；④ 刷新后元素 id 与画布**一一对应**；⑤ 生成的代码含 `gradle wrapper` 与**依赖版本锁定清单**

### E2E-08 S8 测试（三层 + E2E）
- **Given** 预览已刷新
- **When** 进入测试阶段
- **Then** 三层（接口 / App / 埋点）+ E2E 均可执行，且**埋点方案在本阶段被验证**

### E2E-09 S9 交付归档
- **Given** 三层测试通过
- **When** 触发交付
- **Then** ① 输出 Markdown Spec 包 + 安卓工程源码；② 记录版本号；③ 可下载 / 导出（**需鉴权**）
