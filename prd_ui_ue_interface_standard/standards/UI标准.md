# UI 标准（R-UI）

## 0. 定位

UI 回答"**长什么样**"。设计稿本体在 Figma，本目录放的是**可校验的说明**：
Token、状态清单、断点规则、交互态、跳转映射。

**只丢一个 Figma 链接 = 不合格。** AI 读不了你的图层，只能读文字。

---

## 1. 设计 Token（必须成表）

Token 名必须**语义化**且**可直接映射为 CSS 变量 / Tailwind theme**。

| 类别 | 要求 | 映射产物 |
|---|---|---|
| 颜色 | `primary` / `surface` / `error` / `border`，禁止"蓝色-2" | `--color-primary` |
| 字号字重行高 | 成组定义，如 `body-md: 14/400/22` | `--text-body-md` |
| 间距 | 4/8 基准刻度（4,8,12,16,24,32…） | `--space-4` |
| 圆角 / 阴影 / z-index | 全部枚举，无魔法值 | `--radius-md` |

---

## 2. 状态覆盖（AI 最容易崩的地方）

**每个页面必须画全**：

| 状态 | 说明 |
|---|---|
| 默认 | 有数据的理想态 |
| 加载 | **明确二选一**：骨架屏 or spinner（不能"到时候看"） |
| 空 | 与 PRD 的"首次为空/筛选后为空"对应 |
| 错误 | 页面级错误样式 + 重试按钮 |
| 无网络 | 与普通错误是否区分？ |
| 无权限 | 与未登录是否区分？ |
| 极端数据 | 超长文本折行、0 条、999+、数字溢出 |

> **只画了理想态的设计稿，AI 会自行发明其余状态。**

---

## 3. 响应式（必须有）

- 断点定义（如 `sm 640 / md 768 / lg 1024 / xl 1280`）
- **每个页面在每个断点下的布局变化**：PC 三栏→Pad 两栏→手机单栏是否成立？
- 表格在窄屏：横向滚动 还是 变卡片列表？（必须二选一写明）
- 弹窗在移动端的形态（居中 / 底部抽屉）

---

## 4. 交互四态（前端特有）

Android 只需默认态，Web 还需：

`默认` / `hover` / `active` / `focus` / `disabled`

**focus 态尤其重要**——它决定键盘可达性（a11y）。漏了就等于不支持键盘操作。

---

## 5. 跳转映射

每个可点元素必须标注：**跳哪个路由 / 带什么参数 / 本页刷新还是新开页**。

参数名必须与 `数据字典.csv` 中的字段英文名一致。

---

## 6. 规则表

| ID | 规则 | 等级 | 判定方式 |
|---|---|---|---|
| R-UI-001 | 提供设计 Token 表（颜色/字号/间距/圆角/阴影/z-index） | 阻断 | 机检+AI检 |
| R-UI-002 | Token 命名为语义化，非"蓝色-2"式 | 警告 | AI检 |
| R-UI-003 | 每个页面提供全部状态稿（见第 2 节七种） | 阻断 | AI检 |
| R-UI-004 | 每个断点下的布局变化有说明 | 阻断 | AI检 |
| R-UI-005 | 交互元素含 hover/active/focus/disabled 四态 | 严重 | AI检 |
| R-UI-006 | 每个可点元素标注跳转路由与参数 | 阻断 | AI检 |
| R-UI-007 | 组件命名与代码组件名一致 | 警告 | AI检 |
| R-UI-008 | 图标资源格式与命名规则明确 | 建议 | AI检 |
| R-UI-009 | 暗色模式（如需）同期出稿 | 警告 | AI检 |
| R-UI-010 | 多语言（如需）同期出稿 | 警告 | AI检 |
| R-UI-011 | 标注可提取（尺寸/色值），非只有截图 | 严重 | AI检 |
| R-UI-012 | 极端数据态（超长/0条/999+/溢出）已画 | 严重 | AI检 |
| R-UI-013 | 加载态明确二选一（骨架屏/spinner） | 严重 | AI检 |
| R-UI-014 | 表格窄屏策略明确（横滚/变卡片） | 严重 | AI检 |
| R-UI-015 | 提供可访问的 Figma/设计稿链接（非"待提供"占位） | 阻断 | AI检 |
| **R-UI-016** | **断点区间互斥且完备（无重叠、无空隙），且与 PRD 取值一致** | **阻断** | **机检** |
| **R-UI-017** | **设计稿链接真实可访问，非"由设计团队提供"式占位** | **阻断** | **AI检** |

## 7. 断点必须是"划分"，不是"描述"（R-UI-016，本轮新增）

本轮校验发现 PRD 与 UI 的断点表**三处互相重叠**：

| 来源 | 断点定义 |
|---|---|
| PRD §9 | 手机竖屏 375–430；手机横屏 667–**932**；平板 **768** 及以上；折叠屏展开态 **600** 及以上 |
| UI §4 | 手机竖屏 375–430；手机横屏 667–**932**；折叠屏展开 **600–840**；平板 **768** 及以上 |

重叠点：`667–932` 与 `768+`、`667–932` 与 `600+`、`600–840` 与 `768+`。

**前端无法据此写出互斥的媒体查询**——768–840 区间同时命中三个规则，取哪个由实现者随手决定，
于是同一个页面在不同人手里长得不一样。

正确形态必须是**首尾相接的划分**：

| 断点 | 区间 | 布局 |
|---|---|---|
| sm | < 600 | 单列 |
| md | 600 – 767 | 单列居中 |
| lg | 768 – 1023 | 双列 |
| xl | ≥ 1024 | 双列宽 |

判定口径：
1. 区间两两不重叠（前一区间上限 < 后一区间下限）；
2. 区间并集无空隙（覆盖最小到最大）；
3. **PRD 与 UI 两处取值完全一致**。

---

## 8. 链接可访问 ≠ 链接存在（R-UI-017，本轮新增）

本轮 UI 说明第 1 节写的是：

> Figma：由设计团队提供，本文件交付时尚未挂载

这句话**机检完全判不出来**（有"Figma"关键词、有链接位），但是一条**真实的阻断项**：
没有设计稿，UI 说明就只是一份文字规格，颜色对不上、间距对不上、图标对不上。

所以 R-UI-015 的判定方式已从"机检"改判为"**AI检**"，
并新增本条要求 AI 明确判定"这句话是在提供链接，还是在为空缺找理由"。

**这条也提醒了一件事**：机检全绿不代表文档可用。机检只覆盖确定性规则，
凡是"一句话说得像那么回事、实际什么都没有"的问题，只能靠 AI 语义检。
