# UE 标准（R-UE）

## 0. 定位

UI 是"长什么样"，UE 是"**怎么动、怎么错、怎么退**"。

UE 文档缺失时，AI 不会报错——它会**编一套看起来合理的交互**写进代码，然后在联调时全部推倒。

---

## 1. 流程图

- 必须含**全部分支与返回路径**，只画主流程等于没画
- 每个节点的状态机：`触发 → 中间态(loading/禁用) → 结果态 → 回退方式`
- 多入口进入同一页面时，返回键去哪（策略必须唯一）

---

## 2. 路由表（前端特有，必须成表）

| 路由 | 参数 | 参数来源 | 刷新后状态保持 | 支持深链接 | 守卫 |
|---|---|---|---|---|---|
| `/order/list` | `status?` | URL Query | 是 | 是 | 登录 |

必须写明：

- 路径命名规则与参数编码方式
- **刷新后状态是否保持**（存 URL / 存 store / 丢失）
- 是否支持分享深链接
- 浏览器前进后退行为是否与 App 内导航一致

> 路由没定义 → AI 自己起路径名 → 刷新 404。

---

## 3. 请求层行为

| 项 | 必须明确 |
|---|---|
| 防抖/节流 | 搜索框输入阈值（如 300ms） |
| 并发 | 同时发起多请求时，以哪个为准（取消旧的 / 忽略旧的） |
| 取消 | 组件卸载时是否 abort |
| 超时重试 | 超时时间、重试次数、是否自动重试 |
| 缓存 | 是否缓存、缓存多久、何时失效 |

---

## 4. 鉴权与权限

- 登录过期：**静默刷新 token** 还是 **跳登录页**？刷新失败怎么办？
- 被踢下线：如何提示、是否保留当前页
- 路由守卫规则：哪些路由需要登录 / 需要什么角色
- 按钮级权限：无权限时是隐藏还是禁用（必须二选一）

---

## 5. 错误处理（必须集中定义）

- 全局 ErrorBoundary 行为：白屏 / 错误页 / 自动上报
- 接口异常的统一提示形态
- **每个错误码的展示形态与文案**，权威源是 `docs/错误码文案表.csv`
  - `toast` / `页面级` / `弹窗` / `字段级` / `静默`
- 错误文案必须是**最终展示给用户的原话**，不得写"提示错误"

---

## 6. 文案表

**全部用户可见文案集中成表**（含按钮、空态、错误、二次确认）。
这是 AI 写 i18n 文件的**唯一来源**。

---

## 7. 规则表

| ID | 规则 | 等级 | 判定方式 |
|---|---|---|---|
| R-UE-001 | 交互流程图含全部分支与返回路径 | 阻断 | AI检 |
| R-UE-002 | 提供路由表（路径/参数/刷新保持/深链接） | 阻断 | 机检+AI检 |
| R-UE-003 | 表单校验时机与错误文案原文明确 | 严重 | AI检 |
| R-UE-004 | 动效含时长与缓动曲线（给具体值） | 警告 | AI检 |
| R-UE-005 | 请求层行为明确（防抖/节流/取消/超时重试） | 严重 | AI检 |
| R-UE-006 | 鉴权交互明确（token 过期/被踢下线的处理） | 阻断 | AI检 |
| R-UE-007 | 路由守卫与按钮级权限规则明确 | 严重 | AI检 |
| R-UE-008 | 本地存储使用规则明确（localStorage/sessionStorage/Cookie） | 建议 | AI检 |
| R-UE-009 | 全局错误兜底策略明确（ErrorBoundary） | 严重 | AI检 |
| R-UE-010 | 全部用户可见文案集中成表，含错误文案 | 阻断 | 机检+AI检 |
| R-UE-011 | 权限申请的触发时机与拒绝后降级路径明确 | 严重 | AI检 |
| R-UE-012 | a11y 要求明确（是否支持键盘操作、级别） | 建议 | AI检 |
| R-UE-013 | 防重复提交策略明确 | 警告 | AI检 |
| R-UE-014 | 弹窗层级与冲突优先级明确 | 建议 | AI检 |
| R-UE-015 | 跨标签页/跨窗口状态同步策略明确 | 建议 | AI检 |
