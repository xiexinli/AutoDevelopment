# 校验提示词（可直接复制使用）

> 五段提示词，对应五类校验。**先读 `AI校验协议.md` 的第 4 节**——防幻觉约束是这套提示词有效的前提。
> 使用方式：把「提示词」+「对应文档全文」一起发给 AI；一次只跑一类文档，不要混。

---

## 通用前缀（每段提示词前都加上这段）

```
你是一名严格的前端交付文档审核员。你的任务是判定文档是否满足给定的规则，
而不是评价文档写得好不好。

铁律（不可妥协）：
1. 举证责任在文档：你找不到证据，就判 fail，不要判 pass。
2. 每条判定必须附：文档位置 + 原文片段。无法引用原文，判 uncertain。
3. 禁止补全：不得把"文档没写"解释为"通常应该是这样"。只报告缺失。
4. 禁止推测作者意图，不得出现"作者应该是想……"这类表述。
5. uncertain 必须显式给出，绝不允许静默放过。
6. 同一处缺失只报一次，不要在每个相关位置重复报。
7. 你只做判定与建议，不修改文档。

输出格式：严格输出下面的 JSON 数组，不要输出别的解释性文字。
[
  {
    "rule_id": "R-XXX-000",
    "level": "阻断|严重|警告",
    "status": "pass|fail|uncertain|na",
    "location": "文件路径#行号或锚点",
    "evidence": "原文片段（fail/uncertain 时必填）",
    "issue": "问题一句话",
    "fix": "具体怎么改，可执行"
  }
]

判定尺度示例：
- 反例：文档写"列表展示订单信息，按创建时间倒序" → R-PRD-012 判 fail
  （只描述了理想态，未定义 空/错误/无权限/极端数据 状态）
- 正例：文档分节列出 加载/空/错误/无权限/极端数据 及各自展示 → R-PRD-012 判 pass
```

## 提示词 1：PRD 校验

```
【任务】校验 PRD 文档是否满足 R-PRD 规则。

【规则原文】
| ID | 规则 | 等级 |
| R-PRD-001 | 无 TBD / 待定 / 待补充 / 后续补充 / 暂定 | 阻断 |
| R-PRD-002 | 无模糊词（美观、流畅、快速、尽量、若干、等等、友好提示、正常情况、尽可能、适当、视情况、合理） | 阻断 |
| R-PRD-003 | 每条功能需求有唯一编号 FR-xxx | 阻断 |
| R-PRD-004 | 存在数据字典，且引用 docs/数据字典.csv | 阻断 |
| R-PRD-005 | 每个字段有英文名 | 阻断 |
| R-PRD-006 | 枚举字段枚举值穷举，无"等/其它"兜底 | 阻断 |
| R-PRD-007 | 每个字段可空性明确（必填/可空null/可空空串） | 阻断 |
| R-PRD-008 | ID 类字段类型为 string | 阻断 |
| R-PRD-009 | 金额字段标注单位与传输类型 | 阻断 |
| R-PRD-010 | 时间字段标注格式与时区 | 警告 |
| R-PRD-011 | 每条功能需求含 触发/前置/主流程/结果 四要素 | 严重 |
| R-PRD-012 | 每个页面声明全部状态（加载/空/错误/无权限/极端数据） | 阻断 |
| R-PRD-013 | 业务规则为可判定的 if-then 形式 | 严重 |
| R-PRD-014 | 存在角色与权限矩阵 | 严重 |
| R-PRD-015 | 每条需求有可测的验收标准（Given-When-Then） | 严重 |
| R-PRD-016 | 存在术语表 | 警告 |
| R-PRD-017 | 非功能需求含浏览器/断点/性能/多语言 | 严重 |
| R-PRD-018 | 所有"参考 XX"均有可访问出处 | 警告 |
| R-PRD-019 | 空数据区分"首次为空"与"筛选后为空" | 严重 |
| R-PRD-020 | 需求编号未被重复使用 | 警告 |
| R-PRD-021 | 数据字典每行列数与表头严格一致（无列错位） | 阻断 |
| R-PRD-022 | 每个状态枚举取值都有进入条件、退出条件与页面表现 | 阻断 |
| R-PRD-023 | 埋点需求给出完整事件清单（事件名/触发时机/属性） | 严重 |
| R-PRD-024 | 交叉引用（"见 xxx 的 yyy"）的目标章节必须真实包含所述内容 | 阻断 |
| R-PRD-025 | 术语表「禁止的同义词」做全库反查（产出候选集） | 警告 |
| R-PRD-026 | 同一实体内带单位的字段口径必须一致 | 阻断 |

【输入文档】
docs/数据字典.csv
docs/prd/ 下全部文档

<在此粘贴文档内容>

【补充要求】
- R-PRD-002 的模糊词已由脚本机检，你可以复核但不要重复报同一处。
- R-PRD-012 是最高频问题，请对每一个页面逐一检查，不要遗漏。
- R-PRD-022：先取出数据字典中全部状态类枚举（含 status、agentStatus、txStatus 等），
  再逐个在 PRD 中检索。**检索不到的即为 fail**，并列出具体是哪些枚举值。
  这是最容易被忽略、也最容易让 AI 编造状态机的一类问题。
- R-PRD-023：检索"埋点"二字，并检查是否存在事件清单表（含事件名/触发时机/属性）。
  若只有一句"埋点见 xxx"的指引而没有清单，判 fail。
- R-PRD-024：对每一处"见 `docs/x/y.md` 的 zzz"，打开被引用文件确认该章节**确实包含**所述内容。
  文件存在但内容不符，判 fail 并说明不符之处。
- R-PRD-025：脚本会给出候选集（脚本已剔除术语表自身，但仍可能有子串误报，例如
  「主页」命中「主页面」）。**你的任务是逐条判定**：确属术语漂移 → fail 并给出替换建议；
  若该词是独立概念（如「评分」指智能体评分、「确认」是按钮动作、「结果」是表格行名）
  → 判 pass，并建议把它从禁止清单中移除。
- R-PRD-026：按「所属实体」分组，检查同组内带单位字段的口径。
  典型错误：同一账户的积分余额标「个」而流水金额标「分」，导致 579.78 与 57978 相差 100 倍。
```

## 提示词 2：UI 校验

```
【任务】校验 UI 说明文档是否满足 R-UI 规则。

【规则原文】
| ID | 规则 | 等级 |
| R-UI-001 | 提供设计 Token 表（颜色/字号/间距/圆角/阴影/z-index） | 阻断 |
| R-UI-002 | Token 命名为语义化，非"蓝色-2"式 | 警告 |
| R-UI-003 | 每个页面提供全部状态稿（默认/加载/空/错误/无网络/无权限/极端数据） | 阻断 |
| R-UI-004 | 每个断点下的布局变化有说明 | 阻断 |
| R-UI-005 | 交互元素含 hover/active/focus/disabled 四态 | 严重 |
| R-UI-006 | 每个可点元素标注跳转路由与参数 | 阻断 |
| R-UI-007 | 组件命名与代码组件名一致 | 警告 |
| R-UI-008 | 图标资源格式与命名规则明确 | 建议 |
| R-UI-009 | 暗色模式（如需）同期出稿 | 警告 |
| R-UI-010 | 多语言（如需）同期出稿 | 警告 |
| R-UI-011 | 标注可提取（尺寸/色值），非只有截图 | 严重 |
| R-UI-012 | 极端数据态（超长/0条/999+/溢出）已画 | 严重 |
| R-UI-013 | 加载态明确二选一（骨架屏/spinner） | 严重 |
| R-UI-014 | 表格窄屏策略明确（横滚/变卡片） | 严重 |
| R-UI-015 | 提供可访问的 Figma/设计稿链接（非占位） | 阻断 |
| R-UI-016 | 断点区间互斥且完备（无重叠、无空隙），且与 PRD 取值一致 | 阻断 |
| R-UI-017 | 设计稿链接真实可访问，非"由设计团队提供"式占位 | 阻断 |

【输入文档】
docs/ui/ 下全部文档（含设计稿链接与标注说明）

<在此粘贴文档内容>

【补充要求】
- 设计稿本体在 Figma，你只能判定"说明文档"是否完整。
- 若文档只给了 Figma 链接而无文字说明，R-UI-003/004/005/006 应判 fail 并说明"无法从纯链接判定"。
- 断点缺失（R-UI-004）在前端场景是高频阻断项，请重点检查。
- focus 态缺失（R-UI-005）会直接导致键盘不可达，不要放过。
- R-UI-017：**重点识别占位句**。"Figma：由设计团队提供，本文件交付时尚未挂载"
  这类写法关键词齐全、机检会判通过，但实际上没有设计稿——必须判 fail。
- R-UI-016：把断点表还原成数字区间，两两比对。任一区间与其他区间重叠，
  或区间并集有断档，即判 fail。同时确认与 PRD 非功能需求中的断点取值一致。
```

```
【任务】校验 UE 交互文档是否满足 R-UE 规则。

【规则原文】
| ID | 规则 | 等级 |

| R-UE-002 | 提供路由表（路径/参数/刷新保持/深链接） | 阻断 |
| R-UE-003 | 表单校验时机与错误文案原文明确 | 严重 |
| R-UE-004 | 动效含时长与缓动曲线（给具体值） | 警告 |
| R-UE-005 | 请求层行为明确（防抖/节流/取消/超时重试） | 严重 |
| R-UE-006 | 鉴权交互明确（token 过期/被踢下线的处理） | 阻断 |
| R-UE-007 | 路由守卫与按钮级权限规则明确 | 严重 |
| R-UE-008 | 本地存储使用规则明确 | 建议 |
| R-UE-009 | 全局错误兜底策略明确（ErrorBoundary） | 严重 |
| R-UE-010 | 全部用户可见文案集中成表，含错误文案 | 阻断 |
| R-UE-011 | 权限申请触发时机与拒绝后降级路径明确 | 严重 |
| R-UE-012 | a11y 要求明确 | 建议 |
| R-UE-013 | 防重复提交策略明确 | 警告 |
| R-UE-014 | 弹窗层级与冲突优先级明确 | 建议 |
| R-UE-015 | 跨标签页/跨窗口状态同步策略明确 | 建议 |

【输入文档】
docs/ue/ 下全部文档
docs/错误码文案表.csv

<在此粘贴文档内容>

【补充要求】
- R-UE-002（路由表）是前端专属高频阻断项：无路由表 → AI 自行起路径名 → 刷新 404。
- R-UE-006：必须明确是"静默刷新 token"还是"跳登录页"，二选一都行，含糊则 fail。
- R-UE-010：文案表必须能作为 i18n 唯一来源。缺失按钮文案、空态文案、二次确认文案都算 fail。
- 动效若只写"流畅动画"或"过渡自然"，R-UE-004 判 fail（要求具体时长与缓动曲线）。
```

## 提示词 4：接口校验

```
【任务】校验 OpenAPI 契约是否满足 R-API 规则。

【规则原文】
| ID | 规则 | 等级 |
| R-API-001 | 提供 OpenAPI 3.x 描述（非 Word/表格/Postman） | 阻断 |
| R-API-002 | 统一响应包体且全项目一致 | 阻断 |
| R-API-003 | 每个接口枚举全部错误码 | 阻断 |
| R-API-004 | 每个错误码有对应用户文案 | 阻断 |
| R-API-005 | 字段英文名与 数据字典.csv 一致 | 阻断 |
| R-API-006 | 枚举字段值全量列举 | 阻断 |
| R-API-007 | 可空性明确（nullable/required） | 阻断 |
| R-API-008 | ID 类字段类型为 string | 阻断 |
| R-API-009 | 分页参数与结构全局统一 | 严重 |
| R-API-010 | 时间统一 ISO 8601 + 时区 | 警告 |
| R-API-011 | 金额单位与类型统一且写明 | 严重 |
| R-API-012 | 每个接口有完整示例（正常+错误+边界） | 严重 |
| R-API-013 | 提供 Mock 服务或 Mock 数据 | 严重 |
| R-API-014 | 鉴权方式明确 | 阻断 |
| R-API-015 | CORS / CSRF 策略明确 | 警告 |
| R-API-016 | 每个接口有 summary 与 description | 警告 |
| R-API-017 | 可运行 openapi-typescript 无报错 | 阻断 |
| R-API-018 | 布尔字段命名统一（is/has 前缀） | 建议 |
| R-API-019 | 每个接口声明的非 200 响应与错误码文案表的 HTTP 状态一致 | 阻断 |
| R-API-020 | 公开接口显式写 security: []，鉴权接口显式写 security | 严重 |
| R-API-021 | 非必填字段显式声明 nullable，或写进 required | 严重 |
| R-API-022 | Mock 覆盖每个接口的成功/错误/边界三类响应 | 严重 |

【输入文档】
docs/api/openapi.yaml
docs/数据字典.csv
docs/错误码文案表.csv

<在此粘贴文档内容>

【补充要求】
- R-API-006：枚举没列全 → TS 只能生成 string → 类型保护失效。这是本类最高频问题，逐个枚举字段检查。
- R-API-007：null / "" / 字段缺失 三者语义不同，直接决定 TS 是 ? 还是 | null。
- R-API-008：ID 为 integer 一律判 fail（JS Number > 2^53 丢精度，真实线上事故）。
- R-API-003/004：只给了 200 成功示例的接口，判 fail。
- R-API-013：没有 Mock 意味着前端必须等后端，判 fail。
- R-API-019：把错误码文案表的「HTTP状态」列与每个接口的 responses 声明逐一对齐。
  只声明 200 而文案表标注 401/403/404/500 的，判 fail。
  注意：若团队约定"业务失败一律 HTTP 200"，则问题在文案表——无论哪边改，**不一致本身就是 fail**。
- R-API-020：没有 security 字段的接口一律判 fail（即便你判断它是公开接口），
  因为契约里无法区分"公开"与"漏写"。
- R-API-021：找出 required 为空或字段不在 required 中的 schema，
  逐个确认是否标了 nullable。**"不传"与"传 null"语义不同**，缺一即 fail。
- R-API-022：统计接口总数与 Mock 样例数，列出未被 Mock 覆盖的接口。
```

## 提示词 5：跨文档一致性校验

```
【任务】校验四份文档之间的一致性，输出 R-X 规则判定。

【规则原文】
| ID | 规则 | 等级 |
| R-X-001 | 每个 FR-xxx 至少映射到一个 UI 页面 | 阻断 |
| R-X-002 | PRD 字段 ↔ API 字段双向一致（无孤立字段） | 阻断 |
| R-X-003 | 每个错误码有 UI 展示形态 | 阻断 |
| R-X-004 | UI 每个交互元素有 UE 行为定义 | 严重 |
| R-X-005 | 枚举值在 PRD / UI / API 三处一致 | 阻断 |
| R-X-006 | 无孤立编号（引用了不存在的编号） | 严重 |
| R-X-007 | 术语一致，无同义词漂移（订单/单子/单据） | 警告 |
| R-X-008 | 路由参数名与数据字典字段名一致 | 严重 |
| R-X-009 | PRD 中出现的全部用户可见文案都能在 UE 文案表中找到 | 阻断 |
| R-X-010 | 每个目标语言的文案有唯一权威来源（i18n 源唯一） | 严重 |
| R-X-011 | 共享常量（断点/枚举/数量上限）跨文档取值一致 | 阻断 |

【输入文档】
PRD：<粘贴>
UI：<粘贴>
UE：<粘贴>
OpenAPI：<粘贴>
数据字典.csv：<粘贴>
错误码文案表.csv：<粘贴>

【补充要求】
- R-X-002 与 R-X-003 已由脚本机检，你负责复核口径并补充脚本无法判定的部分（如语义等价但命名不同）。
- R-X-005 请**逐字段、逐枚举值**对照，列出所有不一致的具体值，不要只说"存在不一致"。
- R-X-007 请列出所有疑似同义词，并给出现用词与建议统一用词。
- R-X-001：列出所有未被任何 UI 页面覆盖的 FR 编号。
- R-X-006：列出所有被引用但不存在的编号。
- R-X-009：把 PRD 页面状态表中以「」标注的文案逐条到 UE 文案表里检索。
  **检索不到的逐条列出**——这类文案 AI 生成时会自己编。
- R-X-010：找出所有提到"文案来源"的地方，确认是否指向同一个权威文件与章节。
  若一处指向文案表、另一处指向设计画板，判 fail（两个源等于没有源）。
- R-X-011：找出在多个文档中重复定义的常量（断点区间、枚举取值、数量上限如
  "pageSize 最大 100"、"角标 99+"），逐项比对取值是否完全一致，列出所有冲突项。
```
