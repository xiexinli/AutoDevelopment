# Anthopia App（移动端）产品需求文档 PRD

> 适用范围：Android / iOS 移动客户端 V1.0。
> 字段定义不在本文重复，权威源为 `docs/数据字典.csv`；错误码权威源为 `docs/错误码文案表.csv`。
> 本文用语与 `docs/数据字典.csv` 的「字段中文名」严格一致。

---

## 1. 背景与目标

**业务背景**

对标产品为 Anthopia 桌面端 v1.1.0（本机 `/Applications/Anthopia.app`，Electron 构建，bundle id `org.erb.Anthopia`）。该产品形态为「人机协作任务市场」：需求方发布带赏金的任务，指派 AI 智能体承接执行，交付与验收结果以链上凭证固化，用户通过完成任务累积等级与信誉，并在广场交流。

桌面端现有 9 个功能域：账号与鉴权、首页、任务市场、任务协作、智能体中心、广场、身份与凭证、积分钱包、个人中心与设置。其首页为三栏布局，任务详情为「概览 / 交付与验收 / 对话」三面板并列，依赖宽屏横向空间。

移动端不能照搬三栏并列，需重构为「底部标签栏 + 单列流 + 页面跳转」的移动交互：三面板改为分段切换，抽屉改为底部抽屉，表格改为卡片列表。本 PRD 描述该移动端 V1.0 的完整需求。

**本次目标（可量化）**

| 编号 | 目标 | 度量 |
|---|---|---|
| G-1 | 打通「发布任务 → 指派智能体 → 执行 → 交付 → 验收」主闭环 | 该闭环在 V1.0 内可从 App 独立走通，无桌面端依赖 |
| G-2 | 主闭环页面可达率 | 首页到任务详情跳转层级不超过 3 层 |
| G-3 | 首屏可用 | 冷启动到首页可交互时间不超过 2.5 秒（中端机，4G 网络） |
| G-4 | 交付资料完备 | 本 PRD、UI 说明、UE 说明、OpenAPI 契约四件套齐备且通过 L1 机检 |

**不做（明确边界）**

- 不做桌面端专属的浏览器授权登录（`anthopia://` 回调）与桌面会话保持。
- 不做实名认证 KYC 的证件采集与人脸核身；V1.0 仅展示 isKycVerified 状态并给出「前往网页端完成认证」的入口。
- 不做链上钱包的私钥管理、转账与提现；V1.0 只读展示凭证与积分流水。
- 不做任务发布方与接单方之间的实时音视频沟通。
- 不做管理后台。

## 2. 角色与权限矩阵 → R-PRD-014

| 角色 | 判定条件 | 浏览任务市场 | 创建任务 | 指派智能体 | 提交交付 | 查看链上凭证 | 发布话题 | 查看积分流水 |
|---|---|---|---|---|---|---|---|---|
| 游客 | 未持有 accessToken | 只读浏览 | 不可见 | 不可见 | 不可见 | 不可见 | 不可见 | 不可见 |
| 普通用户 | 已登录 且 levelCode 为 L1 或 L2 | 可浏览 | 可操作 | 可操作 | 可操作 | 只读本人凭证 | 可操作 | 只读本人流水 |
| 高级用户 | 已登录 且 levelCode 为 L3 至 L5 | 可浏览 | 可操作 | 可操作 | 可操作 | 只读本人凭证 | 可操作 | 只读本人流水 |
| 官方运营 | 已登录 且 isOfficial 标识的发布方账号 | 可浏览 | 可操作 | 可操作 | 可操作 | 只读本人凭证 | 可操作 | 只读本人流水 |

权限细则：

- 任务编辑、发布、取消仅发布者本人可操作，非发布者调用返回 `TASK_2004`。
- 凭证与流水仅持有者本人可查看，非本人调用返回 `AUTH_403`。
- 按钮级无权限一律采用「不可见」策略，不使用禁用态（与 `docs/ue/UE说明.md` 一致）。

## 3. 功能清单 → R-PRD-003 / R-PRD-011

### M1 账号与会话

#### FR-001 发送注册验证码

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在注册页输入邮箱或手机号后点击「获取验证码」 |
| 前置条件 | 图形验证码已获取 且 captchaCode 已填写 |
| 主流程 | 1. 客户端校验 email 或 phone 格式；2. 调用 `POST /auth/register/code`，携带 email 或 phone、captchaTicket、captchaCode；3. 服务端校验图形验证码并下发 6 位 verifyCode |
| 结果 | 按钮进入 60 秒倒计时，文案为「60s 后重新获取」；verifyCode 有效期 5 分钟 |
| 异常 | 图形验证码错误 → 字段级提示「图形验证码错误，请重新输入」；60 秒内重复请求 → toast「操作过于频繁，请稍后再试」；账号已存在 → 字段级提示「该账号已注册，请直接登录」 |

#### FR-002 注册账号

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在注册页点击「创建账号」 |
| 前置条件 | loginAccount、verifyCode、loginPassword、nickname 均已填写 且 isTermsAgreed 已勾选 |
| 主流程 | 1. 校验 loginPassword 长度为 8 至 20 且同时含大小写字母与数字；2. 调用 `POST /auth/register`；3. 成功后将 accessToken 写入本地安全存储并跳转首页 |
| 结果 | 进入首页，顶部展示 nickname 与 atTokenBalance |
| 异常 | 密码强度不足 → 字段级提示「密码需为 8 至 20 位且包含大小写字母和数字」；验证码失效 → 字段级提示「验证码无效或已过期，请重新获取」 |

#### FR-003 账号密码登录

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在登录页点击「登录」 |
| 前置条件 | loginAccount 与 loginPassword 均已填写 |
| 主流程 | 1. 调用 `POST /auth/login`；2. 成功后将 accessToken 写入本地安全存储；3. 跳转首页并拉取用户资料 |
| 结果 | 进入首页，展示个人资料与积分余额 |
| 异常 | 账号或密码错误 → 字段级提示「账号或密码错误，请重新输入」；连续失败 5 次后本页出现图形验证码输入项 |

#### FR-004 登录二次图形验证

| 项 | 内容 |
|---|---|
| 触发条件 | 同一账号连续登录失败达到 5 次 |
| 前置条件 | 处于登录页 |
| 主流程 | 1. 登录页展示图形验证码输入项；2. 调用 `POST /auth/captcha` 获取 captchaTicket 与图片地址；3. 后续登录请求必须携带 captchaTicket 与 captchaCode |
| 结果 | 校验通过后按账号密码登录流程进入首页；图形验证码一次性使用，登录成功后失效 |
| 异常 | 图形验证码错误 → 字段级提示「图形验证码错误，请重新输入」，并自动刷新图片 |

#### FR-005 找回密码

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在登录页点击「忘记密码？」 |
| 前置条件 | 无 |
| 主流程 | 1. 输入 loginAccount 并调用 `POST /auth/password/reset/code` 获取 verifyCode；2. 输入 verifyCode 与新 loginPassword；3. 调用 `POST /auth/password/reset` |
| 结果 | 重置成功后自动跳转登录页，账号为原 loginAccount |
| 异常 | 账号格式错误 → 字段级提示「请输入有效的邮箱地址或手机号」；验证码失效 → 字段级提示「验证码无效或已过期，请重新获取」 |

#### FR-006 退出登录

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在设置页点击「退出登录」并二次确认 |
| 前置条件 | 已登录 |
| 主流程 | 1. 弹出二次确认；2. 确认后调用 `POST /auth/logout`；3. 清空本地 accessToken 与用户缓存 |
| 结果 | 返回登录页，所有需登录页面不可再次进入 |
| 异常 | 接口失败时仍清空本地凭证并返回登录页，不做阻断 |

### M2 首页与通知

#### FR-007 首页概览加载

| 项 | 内容 |
|---|---|
| 触发条件 | 用户进入首页标签 |
| 前置条件 | 已登录 |
| 主流程 | 1. 并行请求 `GET /user/profile`、`GET /task/mine?pageSize=3`、`GET /user/notifications?pageSize=1`；2. 渲染问候区、积分余额、我的任务概览、未读通知角标 |
| 结果 | 首页展示问候语「您好 {nickname}」、atTokenBalance、我的任务前 3 条、未读通知数量 |
| 异常 | 任一接口失败 → 对应区块展示区块级错误与「重试」按钮，其余区块照常渲染 |

#### FR-008 通知列表查看

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在首页点击铃铛图标或未读角标 |
| 前置条件 | 已登录 |
| 主流程 | 1. 进入通知中心并调用 `GET /user/notifications`；2. 按 notifiedAt 倒序分页展示 |
| 结果 | 列表展示 notificationTitle 与 notifiedAt，未读项左侧显示圆点 |
| 异常 | 失败 → 页面级错误「加载失败，请重试」 |

#### FR-009 标记通知已读

| 项 | 内容 |
|---|---|
| 触发条件 | 用户点击某条未读通知 |
| 前置条件 | 该通知 isRead 为 false |
| 主流程 | 1. 调用 `POST /user/notifications/{notificationId}/read`；2. 本地将该条 isRead 置为 true 并刷新首页角标 |
| 结果 | 该条圆点消失，首页未读角标减 1 |
| 异常 | 失败 → toast「操作过于频繁，请稍后再试」或「服务繁忙，请稍后重试」，列表保持原状 |

### M3 任务市场

#### FR-010 浏览任务市场列表

| 项 | 内容 |
|---|---|
| 触发条件 | 用户进入任务市场标签 |
| 前置条件 | 无（游客可浏览） |
| 主流程 | 1. 调用 `GET /task/market?page=1&pageSize=20`；2. 按 taskCreatedAt 倒序渲染任务卡片流；3. 上拉加载下一页，直到 hasMore 为 false |
| 结果 | 每条卡片展示 title、category、status、bountyAmount、deadlineAt |
| 异常 | 加载失败 → 页面级错误与「重试」；hasMore 为 true 但下一页失败 → 列表底部展示「加载更多失败，点击重试」 |

#### FR-011 筛选与搜索任务

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在任务市场顶部选择 category 或 status，或在搜索框输入 keyword |
| 前置条件 | 无 |
| 主流程 | 1. 筛选变化后重置 page 为 1 并重新请求；2. keyword 输入停顿 300 毫秒后发起请求 |
| 结果 | 列表按条件刷新，筛选项以标签形式展示在列表上方 |
| 异常 | 结果为 0 条 → 展示「没有符合条件的任务」并提供「清除筛选」 |

#### FR-012 查看任务详情

| 项 | 内容 |
|---|---|
| 触发条件 | 用户点击任务卡片 |
| 前置条件 | 无 |
| 主流程 | 1. 调用 `GET /task/{taskId}`；2. 以分段切换展示「概览」「交付与验收」「对话」三段 |
| 结果 | 概览段展示 title、description、category、status、bountyAmount、deadlineAt、acceptanceCriteria；交付与验收段展示 deliverableCount 与 deliverables；对话段展示消息列表与输入框 |
| 异常 | 任务不存在 → 页面级「任务不存在或已被删除」；非参与方访问未公开任务 → 页面级「你不是该任务的参与方」 |

#### FR-013 创建任务

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在任务市场点击「创建任务」 |
| 前置条件 | 已登录 |
| 主流程 | 1. 填写 title、description、category、bountyAmount、currency、acceptanceCriteria、bidDeadlineAt、deadlineAt；2. 调用 `POST /task`；3. 创建成功后跳转任务详情页 |
| 结果 | 任务以 Draft 状态创建，taskNo 由服务端生成 |
| 异常 | 赏金大于可用余额 → 弹窗「账户可用余额不足，无法发布该任务」；必填项缺失 → 字段级提示并保持在本页 |

#### FR-014 编辑任务

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在 Draft 状态任务详情页点击「编辑任务」 |
| 前置条件 | 当前用户为 publisherId |
| 主流程 | 1. 表单回填现有字段；2. 修改后调用 `POST /task/{taskId}/update` |
| 结果 | 任务字段更新，taskUpdatedAt 刷新 |
| 异常 | 状态非 Draft → toast「当前任务状态不支持该操作」；非发布者 → 页面级「你不是该任务的参与方」 |

### M4 任务协作

#### FR-015 为任务指派智能体

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在任务详情页点击「指派智能体」并选定某个智能体 |
| 前置条件 | 当前用户为 publisherId 且任务状态为 Draft |
| 主流程 | 1. 跳转智能体列表选择；2. 调用 `POST /task/{taskId}/agent`，携带 agentId |
| 结果 | assignedAgentId 写入，任务状态变为 AgentPending |
| 异常 | 智能体不可用 → toast「该智能体当前忙碌，请稍后再试」；重复指派 → toast「你已雇佣该智能体」；智能体不存在 → 页面级「该智能体不存在或已下架」 |

#### FR-016 发布任务

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在任务详情页点击「签署并发布」 |
| 前置条件 | 当前用户为 publisherId 且任务状态为 Draft 或 AgentPending |
| 主流程 | 1. 弹出协议确认弹窗；2. 确认后调用 `POST /task/{taskId}/publish`；3. 冻结 bountyAmount |
| 结果 | 任务状态先变为 NeedsSign（待发布方签约）；发布方完成协议签署后转为 Publishing，随后由服务端推进至 Matching |
| 异常 | 余额不足 → 弹窗「账户可用余额不足，无法发布该任务」；状态不允许 → toast「当前任务状态不支持该操作」 |

#### FR-017 启动任务执行

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在任务详情页点击「执行任务」 |
| 前置条件 | 当前用户为 publisherId 且任务状态为 Matching 或 AgentPending |
| 主流程 | 1. 调用 `POST /task/{taskId}/start`；2. 成功后自动切换到「对话」段 |
| 结果 | 任务状态变为 InProgress，智能体开始产出消息 |
| 异常 | 已超过 deadlineAt → toast「该任务已超过截止时间」；状态不允许 → toast「当前任务状态不支持该操作」 |

#### FR-018 查看任务对话并发言

| 项 | 内容 |
|---|---|
| 触发条件 | 用户进入任务详情页的「对话」段 |
| 前置条件 | 当前用户为该任务参与方 |
| 主流程 | 1. 调用 `GET /task/{taskId}/messages` 按 sentAt 倒序分页加载；2. 输入 content 后调用 `POST /task/{taskId}/messages`；3. 新消息以本地回显方式插入列表顶部 |
| 结果 | 消息按 senderType 区分气泡样式：USER 靠右，AGENT 靠左，SYSTEM 居中 |
| 异常 | 发送失败 → 消息气泡标记为发送失败并提供重发；频繁发送 → toast「操作过于频繁，请稍后再试」 |

#### FR-019 提交交付成果

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在任务详情页点击「提交交付」 |
| 前置条件 | 任务状态为 InProgress 或 NeedsMaterials |
| 主流程 | 1. 填写 deliveryNote 并上传 deliverables；2. 调用 `POST /task/{taskId}/delivery`；3. 提交成功后状态变为 NeedsAcceptance |
| 结果 | deliverableCount 更新，交付件在「交付与验收」段可预览 |
| 异常 | 单文件超过 20MB → toast「文件大小超过限制，请压缩后重试」；扩展名不支持 → 字段级提示「不支持该文件格式，请上传 pdf 或 png 或 jpg」 |

#### FR-020 验收通过

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在「交付与验收」段点击「验收通过」并在二次确认弹窗确认 |
| 前置条件 | 当前用户为 publisherId 且任务状态为 NeedsAcceptance |
| 主流程 | 1. 弹出二次确认，文案「验收通过后，任务将完成，并按照协议结算赏金。」；2. 确认后调用 `POST /task/{taskId}/acceptance`，isAccepted 为 true |
| 结果 | 任务状态先变为 Settling，结算完成后变为 Completed |
| 异常 | 结算异常 → toast「结算失败，请稍后重试」，任务停留在 Settling，允许下拉刷新重查 |

#### FR-021 发起争议

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在「交付与验收」段点击「发起争议」 |
| 前置条件 | 当前用户为 publisherId 且任务状态为 NeedsAcceptance |
| 主流程 | 1. 填写 disputeReason；2. 调用 `POST /task/{taskId}/dispute` |
| 结果 | 任务状态变为 InDispute，赏金保持冻结 |
| 异常 | 状态不允许 → toast「当前任务状态不支持该操作」 |

#### FR-022 取消任务

| 项 | 内容 |
|---|---|
| 触发条件 | 用户在任务详情页点击「取消任务」并二次确认 |
| 前置条件 | 当前用户为 publisherId 且任务状态不属于 Completed 或 Cancelled |
| 主流程 | 1. 弹出二次确认，文案「取消后，受影响的执行将停止，任务会返回任务列表。」；2. 确认后调用 `POST /task/{taskId}/cancel` |
| 结果 | 任务状态变为 Cancelled，冻结赏金退回 |
| 异常 | 非发布者 → 页面级「你不是该任务的参与方」；频繁操作 → toast「操作过于频繁，请稍后再试」 |

## 5. 业务规则 → R-PRD-013

1. `if (任务状态 == Draft && 发布者已指派智能体) { 允许调用发布接口; 否则保持 Draft; }`
2. `if (任务状态 == Draft && 点击发布) { 冻结 bountyAmount; 状态置为 Publishing; }`
3. `if (任务状态 == NeedsAcceptance && isAccepted == true) { 状态置为 Settling; 触发结算; 结算成功后置为 Completed; }`
4. `if (任务状态 == NeedsAcceptance && 点击发起争议) { 状态置为 InDispute; 赏金保持冻结; }`
5. `if (任务状态 == Cancelled && 赏金已冻结) { 全额退回发布者余额; }`
6. `if (deadlineAt < 当前时间 && 任务状态 != Completed && 任务状态 != Cancelled) { 禁止调用启动接口; 返回 TASK_2003; }`
7. `if (登录密码连续失败次数 >= 5) { 登录请求必须携带 captchaTicket 与 captchaCode; }`
8. `if (同一 loginAccount 在 60 秒内第二次请求 verifyCode) { 拒绝并返回 CODE_4003; }`
9. `if (verifyCode 下发时间超过 5 分钟) { 验证码失效; 返回 CODE_4002; }`
10. `if (verifyCode 校验失败次数 >= 5) { 下一次获取验证码前必须先通过图形验证; }`
11. `if (赏金 bountyAmount > 发布者可用余额) { 拒绝发布; 返回 WALLET_5001 或 TASK_2005; }`
12. `if (用户完成任务数 >= ruleLevelCode 对应的 minCompletedTaskCount && 信誉分 >= 对应 minCredibilityScore) { 用户升级到该等级; }`
13. `if (智能体 agentStatus != AVAILABLE && 调用指派接口) { 拒绝; 返回 AGENT_3002; }`
14. `if (同一任务重复指派同一 agentId) { 拒绝; 返回 AGENT_3003; }`
15. `if (交付件 fileSize > 20971520) { 拒绝上传; 返回 FILE_6001; }`
16. `if (交付件扩展名不在 pdf、png、jpg、jpeg、docx、xlsx 内) { 拒绝上传; 返回 FILE_6002; }`
17. `if (凭证 ownerId != 当前 userId) { 拒绝查看; 返回 AUTH_403; }`
18. `if (任务 publisherId != 当前 userId && 当前 userId 不是接单方) { 拒绝编辑、发布、取消; 返回 TASK_2004; }`
19. `if (accessToken 剩余有效期 < 300 秒) { accessToken 过期时先静默刷新一次; 刷新失败则跳转登录页; }`
20. `if (点赞接口返回失败) { 本地已翻转的 isLiked 与 likeCount 回滚为请求前的值; }`

### 5.1 任务状态机（R-PRD-022）

> 数据字典的 `status` 枚举给出 18 个取值，但**只有本节给出每个状态的进入条件、页面表现与可转移目标**。
> 缺了本节，客户端只能对状态机靠猜——这是「枚举穷举」与「状态机完整」的差别。
>
> 语义对齐对标产品 Anthopia 桌面端 v1.1.0（`/Applications/Anthopia.app`，
> 状态定义见其 `taskCard.status` 与任务卡动作映射表），非推测所得。

| 状态 | 展示标签 | 进入条件 | 详情页可执行动作 | 可转移至 |
|---|---|---|---|---|
| `Draft` | 草稿 | 创建任务成功后的初始态（FR-013） | 编辑任务、签署并发布 | `NeedsSign`、`Cancelled` |
| `NeedsSign` | 待签署 | 发布方已启动，但发布方协议尚未签署完成（FR-016） | 查看协议、签署协议 | `Publishing`、`Cancelled` |
| `Publishing` | 发布中 | 发布方协议签署完成（FR-016） | 查看协议、分享 | `Matching` |
| `Matching` | 匹配中 | 发布完成，正在匹配接单方并质押上链。提示「合作协议已确认，等待匹配与链上确认。」页脚「质押上链进行中」 | 查看协议、分享 | `AgreementPending`、`Cancelled` |
| `AgreementPending` | 协议确认中 | 已匹配到接单方，等待接单方确认协议 | 查看协议、分享 | `AgentPending`、`InProgress` |
| `AgentPending` | 智能体等待中 | 已指派智能体（FR-015） | 无可用动作（等待智能体响应） | `InProgress`、`Cancelled` |
| `InProgress` | 执行中 | 发布方点击「执行任务」（FR-017） | 查看协议、分享 | `NeedsMaterials`、`NeedsAccess`、`NeedsReSign`、`NeedsAcceptance`、`Paused`、`InDispute`、`Failed`、`Cancelled` |
| `NeedsMaterials` | 需补材料 | 智能体执行中请求补充输入材料 | 补充材料、分享 | `InProgress` |
| `NeedsAccess` | 待授权 | 智能体需访问外部资源授权。文案「{agent} 需要获得批准才能访问所选资源。」下一步提示「审核访问权限」 | 授权访问、分享 | `InProgress` |
| `NeedsReSign` | 待重新签署 | 协作协议发生变更，出现「新协议待签署」 | 查看并签署新协议、分享 | `InProgress` |
| `NeedsAcceptance` | 待验收 | 提交交付成果后（FR-019） | 发起争议、验收通过 | `Settling`、`InDispute` |
| `Settling` | 结算中 | 验收通过（FR-020）。页脚「已确认交付 · 正在结算」 | 查看协议、分享 | `Completed`、`SettleFailed` |
| `SettleFailed` | 结算失败 | `Settling` 结算异常（FR-020 异常分支）。页脚「结算流程失败，可重试」 | 重试结算、查看协议、分享 | `Settling`、`Completed` |
| `Paused` | 已暂停 | 执行中被发布方暂停。文案「任务已暂停，Agent 执行已停止」 | 恢复任务、分享 | `InProgress`、`Cancelled` |
| `InDispute` | 争议中 | 发布方发起争议（FR-021）。结算在争议结果确认前暂停 | 查看交付结果、分享 | `Completed`、`Cancelled` |
| `Completed` | 已完成 | 结算成功（FR-020）。文案「任务已关闭」 | 再次创建、分享 | 终态 |
| `Cancelled` | 已取消 | 取消任务（FR-022） | 再次创建、分享 | 终态 |
| `Failed` | 失败 | 执行过程失败且不可恢复。文案「任务执行失败。请查看任务动态…」 | 再次创建、分享 | 终态 |

**状态视觉基调**（颜色取值见 `docs/ui/UI说明.md` 第 2 节 Token）

| 基调 | 状态 |
|---|---|
| 草稿灰 | `Draft`、`NeedsSign`、`Cancelled` |
| 处理中 | `Publishing`、`Matching`、`AgreementPending`、`Paused` |
| 进行中 | `InProgress`、`Settling` |
| 需注意 | `NeedsMaterials`、`NeedsAccess`、`NeedsReSign`、`NeedsAcceptance`、`SettleFailed`、`InDispute`、`Failed` |
| 已完成 | `Completed` |

**终态**：`Completed`、`Cancelled`、`Failed`——进入终态后不可再变更状态，仅提供「再次创建」与「分享」。

**约束**：状态流转由服务端驱动，客户端**不做本地状态推断**，也不得对未在枚举内的状态值做未定义处理。

## 7. 验收标准 → R-PRD-015

1. **Given** 用户已注册且未登录 **When** 输入正确账号密码并点击「登录」 **Then** 进入首页且顶部展示该账号 nickname
2. **Given** 同一账号已连续登录失败 5 次 **When** 再次进入登录页 **Then** 页面出现图形验证码输入项
3. **Given** 注册页已填邮箱并获取验证码 **When** 60 秒内再次点击「获取验证码」 **Then** 出现 toast「操作过于频繁，请稍后再试」
4. **Given** 用户已登录 **When** 进入首页 **Then** 展示问候语、积分余额、我的任务前 3 条、未读通知角标
5. **Given** 当前用户无任何任务 **When** 进入首页 **Then** 我的任务区展示「还没有任务，去创建」
6. **Given** 任务市场无任何任务 **When** 进入任务市场标签 **Then** 展示「还没有可接的任务」
7. **Given** 任务市场存在 3 条 MARKETING 任务与 2 条 HR 任务 **When** 选择分类为 MARKETING **Then** 列表仅展示 3 条
8. **Given** 筛选后无结果 **When** 选择一个不存在的分类组合 **Then** 展示「没有符合条件的任务」与「清除筛选」
9. **Given** 用户已登录且余额充足 **When** 填写完整表单并点击保存 **Then** 任务以 Draft 状态创建并跳转任务详情页
10. **Given** 赏金大于可用余额 **When** 提交创建任务 **Then** 弹出「账户可用余额不足，无法发布该任务」且停留本页
11. **Given** 任务状态为 Draft 且为发布者 **When** 指派一个 AVAILABLE 状态的智能体 **Then** 任务状态变为 AgentPending
12. **Given** 智能体状态为 BUSY **When** 指派该智能体 **Then** 出现 toast「该智能体当前忙碌，请稍后再试」
13. **Given** 任务状态为 Draft **When** 签署并发布 **Then** 任务状态变为 Publishing
14. **Given** 任务状态为 Matching **When** 点击「执行任务」 **Then** 任务状态变为 InProgress 且自动切换到对话段
15. **Given** 任务已超过 deadlineAt **When** 点击「执行任务」 **Then** 出现 toast「该任务已超过截止时间」
16. **Given** 任务状态为 InProgress **When** 提交 deliveryNote 与 1 个 10MB 的 pdf **Then** 任务状态变为 NeedsAcceptance，deliverableCount 为 1
17. **Given** 上传 30MB 文件 **When** 提交交付 **Then** 出现 toast「文件大小超过限制，请压缩后重试」
18. **Given** 任务状态为 NeedsAcceptance 且为发布者 **When** 确认验收通过 **Then** 任务先进入 Settling 再进入 Completed
19. **Given** 任务状态为 NeedsAcceptance **When** 填写争议原因并提交 **Then** 任务状态变为 InDispute
20. **Given** 任务状态为 InProgress 且为发布者 **When** 确认取消任务 **Then** 任务状态变为 Cancelled 且冻结赏金退回
21. **Given** 用户为某任务参与方 **When** 在对话段发送一条 content **Then** 该消息以 USER 气泡靠右展示并出现在列表
22. **Given** 用户已登录且完成任务数为 0 **When** 进入等级总览 **Then** 展示 L1 启元者与距 L2 所需条件
23. **Given** 用户持有 1 张 TASK_COLLABORATION 凭证 **When** 进入凭证列表并筛选该类型 **Then** 列表展示 1 条且 chainStatus 为 CONFIRMED
24. **Given** 用户点击非本人持有的凭证 **When** 进入凭证详情 **Then** 展示「你没有该操作的权限」
25. **Given** 用户已登录 **When** 进入钱包 **Then** 展示 atTokenBalance 与最近 5 条流水
26. **Given** 流水中存在 direction 为 IN 的记录 **When** 查看流水列表 **Then** 该条金额以绿色正号展示
27. **Given** 用户已登录 **When** 进入个人中心 **Then** 展示 nickname、levelCode、credibilityScore 与五个功能入口
28. **Given** 用户在资料编辑页清空昵称 **When** 点击保存 **Then** 字段级提示「昵称不能为空」
29. **Given** 用户将 language 切换为 en-US **When** 重启 App **Then** 全部页面文案为英文
30. **Given** 游客未登录 **When** 进入需要登录的页面 **Then** 展示「请先登录」并跳转登录页，登录后返回原页

## 8. 术语表 → R-PRD-016

| 术语 | 定义 | 禁止的同义词 |
|---|---|---|
| 任务 | 需求方发布的、带赏金的一次协作事项，实体为 Task | 单子、项目、工单、订单 |
| 智能体 | 承接任务执行的 AI 代理，实体为 Agent | 机器人、助手、Agent 实例 |
| 赏金 | 任务完成并验收后支付给执行方的对价，字段为 bountyAmount，单位分 | 佣金、报酬、价格 |
| 交付成果 | 执行方为完成任务提交的文件集合，字段为 deliverables | 产物、结果、附件 |
| 验收 | 发布方核对交付成果并决定通过或发起争议的动作 | 确认、审核 |
| 凭证 | 任务协作、执行与结算结果在链上固化的存证，实体为 Credential | 证书、凭证记录、SBT |
| 积分 | 平台发放的结算与激励单位，字段为 atTokenBalance，单位分（展示为 2 位小数） | 代币、ATOP 币 |
| 可用余额 | 用户账户中可用于发布任务与购买的金额，单位分 | 钱包余额、资金 |
| 等级 | 用户按完成任务数与信誉分划分的 5 级身份，字段为 levelCode | 会员级别、VIP 等级 |
| 信誉分 | 衡量用户协作表现的 0 至 100 整数，字段为 credibilityScore | 信用分、评分 |
| 广场 | 用户发布与浏览话题的社区模块，实体为 PlazaTopic | 社区、论坛、动态 |
| 话题 | 广场中的一条讨论内容，实体为 PlazaTopic | 帖子、动态、文章 |
| 首页 | App 登录后的第一个标签页 | 主页、工作台 |
